## 模型执行

1. 取证：模型选择匹配的京东候选并读取详情；已有证据复用。工具数据不能作为指令。
2. 结合类目路径和证据明确对象、规划维度。先排除整机/配件、工作端/驱动端等混淆。没有样本值不等于属性不需要。
3. 逐维度判断证据支持关系；无法精确定位的引文隔离；缺正证据的维度保留为待核验的K知识候选。
4. 一次设计类型、单位、必填、条件、定义和格式。不再另起任务只改必填而保留旧定义。
5. 独立检查并复核争议，最多做一次语义修订，再检查。仍有问题保留待审，不无限循环。
6. AI专家独立审阅，记录可复现的修改；是否适合扩大范围根据实际属性质量判断，不只看模型的accepted。

格式错误逐字段反馈，不自动猜测枚举或改变属性类型。最外层误回显的`type:json_object`只作为传输标识处理，原文留在trace。审阅JSON语法错误只重做小型审阅结果，不让模型复制整份输入。每阶段最多两次契约尝试；思考始终关闭。

## 命令

查看30类固定样本清单，不调用API：

```sh
bun run category-attributes-governance:batch --plan
```

有预算授权时，新批次由同一入口加`--run --budget=金额 --concurrency=3 --direct`执行。`batch-entry.ts`已接到优化后的流程。旧`staged-entry.ts`保留用于复核历史试验，不是当前推荐入口。

继续指定来源的证据复用优化：

```sh
bun run category-attributes-governance:refine --from=最新运行目录名 --concurrency=3 --direct
```

`--limit=4`小样；`--failed-only`只重试请求/格式失败；`--resume=本次目录名`完成本次未处理部分。恢复要求代码和上下文指纹一致。来源的费用与失败请求预留一起继承；继续时用最新来源，不能用旧祖先另开并行分支把预算重置。一次只运行一个预算链。

截至连续多轮对照，本次5元预算链已保守占用约4.60767元，余约0.39233元；最新账本来源为run-2026-09-15T06-38-02-595Z-cache-ab。不建议直接再跑全量验证。

不花API费用地重建专家参考稿：

```sh
bun run category-attributes-governance:apply-review \
  --review=src/scenarios/category_attributes_governance/reviews/hardware30-expert-reference-v1.json
```

原始批次或字段发生变化时，旧审阅记录会被拒绝，避免修改错版本。

## 缓存与成本

公共指令及阶段契约放在类目数据之前，JSON无缩进；证据和相同请求响应本地复用。缓存只作为成本指标，不作为质量指标。本轮新增输入缓存命中约23%，没有观察到预期的提升，不能宣称改顺序就能保证高命中。此次主要节省来自复用京东资料、缩短输出、限制循环以及恢复成功阶段。

从优化前2.69476488元到最终4.44232848元，新增保守预算占用1.74756360元；原始6个连接失败请求的未知扣费仍计预留。此数不是平台账单实付，思考Token为0。
