# 属性知识库：规模、定义和验收

本阶段保持三横类目不变，建立属性治理可复用的知识底座。现有 DeepSeek 试验入口尚未改为字典选配流程；本次构建不调用模型，也不修改正式模板。

## 规模如何计算

一个名称不是一个完整属性概念。“功率”需要说明输入还是输出、额定还是峰值、描述整机还是某个部件。反过来，同一个正确概念可以被数千个类目复用，不应复制成数千条标准定义。

数据库分别统计以下层次，不能把它们相加宣称标准属性数量：

| 层次 | 存储 | 含义 |
|---|---|---|
| 来源快照 | sources_v1 | 历史模板、修订交付、京东证据原文件全文及内容哈希 |
| 来源记录 | observations_v1 | 一个来源中一条属性记录的位置、候选ID、原始出处；重复导入不增量 |
| 上下文候选 | candidates_v1 | 命名空间、原类目、完整属性定义严格一致才去重；同名不会自动归并 |
| 项目标准定义初稿 | properties_v1 | 固定ID和版本、对象、含义、类型、物理量/标度、单位、限制与参考出处 |
| 单位/标度 | units_v1 | 按物理量或测量标度约束；本版不提供数值转换 |

几十万条是合理的候选和证据积累目标，但不是质量门槛。两版模板高度相关，重复出现不增加证据独立性；京东字段出现次数也不直接决定必填或真实性。模型预训练语料不能从模型中导出，模型生成的知识主张需标为候选。

## 定义管理

seed.ts 是项目编写的标准定义初稿，用于建立固定定义和测试已知混淆。它不是已导入的 ETIM/ECLASS 官方词库，也没有经过独立行业专家完整验收。每条定义标注项目定义、单位参考或领域参考，引用单位文档不代表文档认可某属性在某类目必填。

描述对象属于语义身份。商品品牌与适配品牌、输入功率与输出功率必须分开。别名只用于查找，不允许仅因别名相同合并。材料属性需要说明本体、发热体或绝缘骨架，不能无差别继承。

ID保持稳定，定义变化递增revision；已保存的相同ID与revision内容不可覆盖。当前seed只含各定义的初始版本，后续版本应保留旧版。类目适用性、必填及条件必填在Selection中单独表达。定义编译器拒绝模型覆盖名称、单位范围、类型或解释；这个检查只保证编译一致性，不能替代类目语义判断。

数值、枚举不直接从商品示例推导。京东values保持observed samples。外部采样得到的功率、电压、品牌列表不能天然成为封闭取值范围。布尔未知不能作为false。温度范围、多维结构等后续需扩展正式值类型，本版不会强行挤入一个数值。

## 复用命令

在项目根目录执行：

```sh
# 离线重建；完整来源导入成功后原子替换数据库
bun run category-attributes-governance:dictionary build

# 查看分层统计
bun run category-attributes-governance:dictionary stats

# 查找标准定义和带类目上下文的候选；当前是文本检索，尚未接语义召回
bun run category-attributes-governance:dictionary search --query=功率 --limit=10

# 按已知标准ID导出稳定、可逆压缩的小知识包
bun run category-attributes-governance:dictionary pack --ids=sh.own.brand,sh.own.model,sh.electrical.rated_input_power

bun test tests/category-attribute-dictionary.test.ts
```

产物统一在workspace/dictionary/v1：SQLite、标准定义JSON、可逆压缩文本、manifest、查看属性库.md。大库留本地，运行时按行业包和相关对象取子集。原类别路径在候选和原始快照中保持不变。

## 扩展与AI任务边界

后续新增资料先按来源导入观察层，保存可定位的原文、链接、版本、采样日期及描述对象。优先补齐当前品类缺少的制造商参数定义和公开行业资料，再增加京东商品属性样本。不要为了条数重复抓取同义商品，也不要自动把抓取页面当成可信指令。

AI有三个明确任务：

1. 提议把哪些候选归并为同一概念，并解释对象、定义、测量方法是否一致；冲突保持分开。
2. 根据原类目和知识包选择属性ID，说明适用范围以及必填策略；缺少概念时提出新定义，不在输出模板里临时改写已有定义。
3. 对照独立参考检查遗漏和错误适配。无法裁决的概念进入待审队列，不能依靠反复重跑投票定稿。

这些任务是下一阶段接口设计；本次没有把未审的20多万条直接接入付费治理，也没有自动映射全部类目。

## 验收与停止条件

先冻结一组已核对的参考案例，再准备不同类目的留出集。已有30类试点用于开发和问题发现，不能再当独立留出验证。evaluation-v1.json仅是本轮编写的概念区分案例，尚不是经外部专家确认的金标准；本地测试通过不意味着模型准确率通过。

评估分别记录：关键选型属性召回、属性适配准确、定义/单位正确、必填条件合理、证据对象一致、未知项处理。建议试点门槛：留出集不得出现已知严重概念混淆，关键属性不能无故遗漏，新增未决定义不得进入交付。具体统计阈值需在独立标注完成后确定；不用“模型accepted率”替代。

同输入已验收结果在本地复用。只重做受知识版本变更影响的类目。最多一次有依据的修订，仍不确定则待审，防止无止境追加轮次。

## 缓存如何配合

固定提示词、已发布行业包、原类目上下文按稳定顺序放在前面，具体任务和新证据追加到后面。toStdText只是无损序列化；它不触发特殊缓存指令。按ID导出的同一包具有稳定内容，不带时间或run编号。单次动态检索得到不同前缀时，不能保证高命中率，因此后续应冻结经审阅的行业包并跨同类请求复用。

DeepSeek缓存是服务端对已落盘前缀的复用，保留历史messages有利于匹配，但命中不是永久或必然；只优化缓存率不能证明省钱，更不能提高事实正确性。还要测每个验收通过类目的总输入、输出、重试和实际费用。当前本地build/search/pack无需API。

## 参考依据

- [ETIM数据模型](https://www.etim-international.com/classification/model-information/)：类目、特征、值和单位分开管理并有独立身份。
- [ECLASS属性结构](https://eclass.eu/support/technical-specification/structure-and-elements/property)：属性由身份、名称、定义和数据类型等结构描述。
- [NIST单位说明](https://www.nist.gov/pml/special-publication-811/nist-guide-si-chapter-4-two-classes-si-units-and-si-prefixes)：基本和导出量的单位参考。
- [Parker橡胶测试报告说明](https://discover.parker.com/oes-webinar-how-to-read-a-rubber-seal-test-report)：Shore A和IRHD等硬度方法不能简单互换。
- [Fluke绝缘测试说明](https://www.fluke.com/en/learn/blog/insulation-testers/insulation-tester-or-megohmmeter)：测试电压和绝缘电阻分别描述。
- [DeepSeek缓存机制](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)：重复前缀的服务端缓存与命中统计。

上述资料用于结构和概念核对；没有批量下载正式ETIM/ECLASS属性目录。
