# 当前试验流程：有限多轮与独立语义核验

只治理类目属性，保留三横类目名称、ID和层级。思考关闭。预算默认10元，延续同一验证链的累计账本；每一轮不是重新获得10元。当前是2类试验入口，尚未替代旧batch入口，也未发布正式模板。

## 一次执行的工作

1. **资料对象筛选**：AI判断本类对象、关联对象、不相关或不确定。只有本类资料进入生成，原始被排除资料仍存档。
2. **独立选型需求**：不看生成器计划或模板。分清产品固有属性、额定能力、随附配置与客户现场条件；后者不是需要补齐的商品属性。
3. **连续生成**：同一对话明确属性计划、判断引用关系、生成完整模板。固定类目与资料只放首轮，保留逐字模型响应，只追加新的任务及约束。
4. **独立证据核对**：每条拟采用的引用，检查原文是否真的表达目标属性；不支持或不确定的链接退回K知识候选。引用白名单不证明行业事实正确。
5. **独立覆盖与逐行核验**：需求逐项映射到属性，允许多个字段联合覆盖；不存在的属性可直接标missing。名称含义和定义含义分开检查。原生成对话不发送给审阅器。
6. **一次修订**：仅发未解决问题和相应需求；已通过检查不重发。可以新增缺失字段，新增字段暂用K，不能借用其他字段的外部证据。随后再验收，未解决项保留待审。
7. **发布前独立复核**：模型accepted仅为内部检查状态，不能自动成为正式模板。专家判断与原始模型输出分别保存。

不依赖类目名关键词硬编码行业模板；代码检查ID、类型、引用定位、需求覆盖、预算和状态。语义判断由模型完成，因此仍须用回归样本验证它是否判断准确。

## 执行入口

默认验证O形圈、热风枪发热芯两类，复制命令会真实调用API；相同完整请求本地复用：

```sh
bun run category-attributes-governance:semantic \
  --from=run-2026-09-15T07-09-52-290Z-semantic-regression \
  --budget=10 --direct
```

`--category=类目名称`只处理该类，目前限制在已批准的五金工具30类固定样本中。`--resume=运行名`继续预算中断或未完成部分，代码指纹变化会拒绝覆盖。格式/请求失败已写入结果时，用最新运行作`--from`再启动，复用已有请求。不要同时启动不同预算链或用旧祖先账本重置费用。

输出位于 `workspace/output/run-时间-semantic-v3/`：

- `semantic-results.json`：仅本次实际处理的类目。
- `results.json`：30类来源集与本次结果合并，未处理的28类仍是历史结果，不能据此宣称30类已通过新流程。
- `查看结果.md`：本次模板，状态是模型内部判断；其中Token和费用为累计值。
- `semantic-status.json`：本次新增请求/费用、预算停止状态，以及累计统计。
- `categories/类目ID/`：资料范围、独立需求、引用核对、各阶段输出；中断结果单独为partial-result。
- `trace.jsonl`、`usage.json`、`responses.json`：原始请求响应、累计账本、本地完整响应缓存。

## 回归已知错误

```sh
bun run src/scenarios/category_attributes_governance/semantic-regression-entry.ts \
  --from=最新预算运行名 \
  --cases=src/scenarios/category_attributes_governance/reviews/semantic-regression-v1.json \
  --direct
```

`reviews/semantic-regression-v1.json`来自历史实际错误。期望答案仅在本地比对，不发送给模型。包含错误引用、名称/定义对象混淆、电气物理量混淆，另有正确品牌引用作为对照。回归命中率不是全量准确率。
