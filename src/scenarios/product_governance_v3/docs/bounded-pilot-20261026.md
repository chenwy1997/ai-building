# 三类试点：增量合同与有限验收

范围：洗脸巾、盒装抽纸、软包抽纸。2026-10-26研发改造；只离线验收，无新DeepSeek请求、生产写入、人工采用或预算调整。思考档位保持low。过去真实结果原件保留，不按新规则原地改成通过。

## 这次改变的执行方式

此前模型既判断业务，又抄写共同定义、绑定和数量字段名。相同的定义在同族末级重复输出，任何润色都可能触发R03纠错；unitMin职责组与unitMinQua数量列也被反复混淆。新合同让这两部分成为确定性装配。

| 内容 | 模型负责 | 程序负责 | 仍需人工 |
| --- | --- | --- | --- |
| 同族共同定义 | 引用baselineVersion；新增参数与修订建议 | 展开全部定义/绑定/决策，携带未决事项；禁止重复及覆盖 | 共性是否成立、修改建议是否采用 |
| 非本族属性池引用 | 选择attributeId、definitionHash并解释用途 | 固定定义原样读取，继续检查全部目标的适用范围 | 新的跨类范围核实 |
| 数量职责 | 对象、计数词、measure、same/conditional等关系 | 生成unitMin职责、unitMinQua数量列、salesUnit分母对照与来源计划 | 业务判断及未来具体SKU单位核实 |
| 扩展候选 | 业务/专业/范围待解决事项 | 拒绝已知“先确认必填/先稳定取得SKU值”门槛 | 专业口径是否已解决 |
| 相关参数检索 | 比较命中对象与计量状态 | 单张尺寸/纸张尺寸、材质/原料等相关词召回 | 是否同义；召回不授权复用 |

`modeling-proposal.ts`保存模型增量schema与装配逻辑。`runner.ts`先验证增量，再装配、运行原检查和原生配置投影，记录原提案、基线内容hash、数量映射、修改建议及完整结果hash。`batch-recovery.ts`从原响应再次装配并比对，不把已展开结果冒称模型原话。

新建批次与显式新轮次冻结`modelingContractVersion`；历史无版本记录仍按旧合同读取。新材料/检查变化继续阻断旧结果的跨版本自动恢复。没有替用户创建付费新轮次。

技能已按增量工作方式重写，全文与判例仍通过release进入instructions。专门研究包`wash-tissue-research-20261026`通过真实类目ID要求载入，工具可读正文。默认新批次与源自默认profile的新轮次均会接入；原快照不变，自定义快照仍需显式配置自己的知识要求。

补入专业资料后，较大的历史抽纸基线曾再次超过200 KB输入上限。现在只把属性池中与当前请求同族全文完全一致的重复定义替换为`context_definition_reference`，注明全文位置和hash；同族全文、配置、决策、引用及全部知识分片仍保留，原工具读取记录不变。回归会解析引用并核对完整对象，未增加输入上限或截断资料。

## 真实案例与覆盖范围

`fixtures/pilot-applicability-20261026.json`保留本轮三个真实最终业务输出、程序反馈和来源hash，不含思考过程或凭证；它们是问题回归材料，不是标准答案。

- 软包共同定义/候选被复制改写：引用装配后逐项保持原值。共享修订另列，原叶属性不被替换。
- 数量字段名混淆：增量schema不接收systemFieldKeys、自由同/异条件或重合动作；宿主生成这些内容，仍校验关系是否合理。
- 香型的“确认必填必要性”和克重的“包装标注可稳定取得”：从真实原文提取负例，程序拦截；核实专业口径、明确说明取值不决定准入等正例保留。
- 属性池单张尺寸、材质检索遗漏：相关词补充召回，目标适用性仍独立拒绝未经核实的外推。
- 历史缺失decisions：上下文列assessmentNeededIds，输出缺失仍报错，不由宿主补成confirmed。
- 同族未决问题随基线版本继承，不能因为末级只输出引用而丢失。

自然语言检查只覆盖明确表达，不能证明所有业务理由正确。改ID同时大幅改写口径的隐性重复、必要性自述的真实性、行业术语边界仍需人工样板裁定。提高思考档位不是这些工程缺口的修复手段。

## 本轮评审清单与停止条件

核心清单见[专业研究包](../knowledge/wash-tissue-research-20261026.md)：抽纸核对原料、层数、单张尺寸、内装数量及香型的选择价值；洗脸巾核对基材、单张尺寸、内装数量。此清单待业务审阅，不强制输出固定数量的属性，也不是全清洁纸品标准。

| 问题级别 | 本轮处理 | 结束要求 |
| --- | --- | --- |
| 工程错误 | 修复合同、装配、工具历史、恢复及日志问题 | 回归和实际离线调用链通过，无模型联网 |
| 已定规范违反 | 共享变更、范围外套用、职责重复、必填冲突等必须拒绝或隔离 | 真实负例仍被识别，合法正例不被误拦 |
| 专业待裁定 | 核心概念、适用范围和枚举边界，列依据与责任角色 | 每个问题有明确去向；未定项暂缓，不能伪装批准 |
| 文字/扩展建议 | 收入后续候选清单 | 不为消灭所有建议反复付费跑同一批 |

人工待裁定集中为三组：

1. **采购/运营**：核心清单与香型的业务选择价值；独立长宽是否必要。未定是否强制填写时先选填。
2. **类目负责人**：洗脸巾是否包含耐用毛巾；有限次复用宣称如何解释。当前不确认“一次性/可重复使用”互斥枚举，不扩类。
3. **专业/类目审阅者**：卷纸既有定义能否扩展到抽纸或柔巾、尺寸状态与内装数量分母。没有人工范围记录时继续暂缓相应共享ID；抽/张/片不无证据换算。

工艺、湿强、克重的完整研究不列为本轮完成前提；对应候选保留。人工尚未裁定的专业项不能通过模型换一版措辞就算解决。
