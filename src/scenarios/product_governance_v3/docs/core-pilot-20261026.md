## 跨类复用核实

| 定义 | 盒装/软包抽纸 | 洗脸巾 |
| --- | --- | --- |
| roll.layers：成品纸张叠层数 | 定义没有限定卷状，原样复用，保留层单位 | 不外推；层数不在本轮核心 |

## 数量字段职责

本地供应链代码复核保存于`knowledge/native-quantity-carrier-20261026.json`，包含三个文件的内容hash。`CategoryKeyConfig`定义默认键`unitMin`、`unitMinQua`、`saleUnit`；`salesUnit`仅是治理职责名。真实实例值由`PropertyInstance`/`PropertyValueInstance`及商品实例关联承载。`StdProduct`存在`saleUnit`，但同步映射明确把`unitMin`与`unitMinQua`列为缺失字段，不能假装这两项是StdProduct列。

| 条件例子（演示口径，不是SKU事实） | 职责计划 |
| --- | --- |
| 销售单位=盒，最小单位=抽，数量=100；目标100抽/盒 | 对象、分母、计数词核实一致后复用原生值，不二次填写 |
| 销售单位=提，最小单位=盒，数量=3；目标100抽/盒 | 后台表达3盒/提，目标表达每盒内容物；独立内装参数 |
| 销售单位=袋，最小单位=包，数量=6；目标100片/包 | 外包装包数与内装片数不同，不能互相覆盖 |
| 原生计数词=张，来源=抽，或单位未知 | 不按层数乘除、不猜等价，具体SKU待核实 |

因此三类内装数量用`conditional`来源计划，不整类判成系统已有，也不一概独立。宿主记录实际承载、默认键、待读取的配置键及重合/不重合条件；继承末级也保留该计划。当前未读取逐SKU配置和值，不执行条件分支或填写数据。未来执行须先解析实际CategoryKeyConfig，再核对SKU计数对象与层级。
