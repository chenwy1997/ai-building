## 直接执行

项目根目录先预检，无模型请求、无需密钥：

```sh
bun src/scenarios/product_governance_v3/cli.ts batch \
  --category-id 77e31cf2-8331-4c73-ab10-823d2d1d7ab0 \
  --concurrency 32 \
  --out outputs/product-governance-v3/clean-paper-batch-20261023
```

该ID是当前治理树的“清洁用品>清洁纸品”，展开21个末级。将`DEEPSEEK_API_KEY`放在环境变量或本地`.env`（Bun自动加载）后，加`--execute`才会请求付费DeepSeek：

```sh
bun src/scenarios/product_governance_v3/cli.ts batch \
  --category-id 77e31cf2-8331-4c73-ab10-823d2d1d7ab0 \
  --concurrency 32 \
  --out outputs/product-governance-v3/clean-paper-batch-20261023 \
  --execute
```

没有密钥在请求前报错。入口不查询公共库或供应链密钥，不把密钥放入参数、请求文件或日志。本次开发未启动真实DeepSeek批次。

## 参数

| 参数 | 含义 |
| --- | --- |
| `--category-id` | 必填；上级展开所有后代末级，末级只跑这一类，同族其他成员只作上下文；须为所用治理树ID，不能混用商城/后台另一套目录ID |
| `--concurrency` | 整数1—128，默认8；32是上限，不会凑任务数或破坏同族依赖；恢复时可调 |
| `--out` | 同一批始终用同一目录；省略时固定为`outputs/product-governance-v3/attributes-类目ID`，不跨天自动新建批次 |
| `--run-id` | 默认输出目录的绝对路径，恢复保持不变 |
| `--tree` | 显式类目树；默认优先本机`outputs/category-id-refresh-20261021/mapped-tree.updated.json`完整树，缺失时回退到随代码提交的清洁纸品26节点摘录（21末级及祖先）。摘录仅能检索摘录内节点 |
| `--snapshot` | 与`--tree`互斥；已有format=2本地业务快照，可用于其他根类目，必须有完整字段职责、适用知识要求和可用同族状态；fixture拒绝进入批处理 |
| `--budget-cny` | 默认200元保守预留封顶，**不是预计账单**；全批共享，恢复不得隐式提额或清零 |
| `--execute` | 明确请求付费模型；省略只预检 |
| `--log-format` | `human`（默认）、`json`或`quiet`。正常开始、逐轮请求/响应、缓存、完成走stdout；实际阻断走stderr。`quiet`仅输出最后JSON汇总 |
| `--no-excel` | 先只保存JSON，稍后`batch-export`补导，无需重调模型 |
| `--freeze-left` | Excel左侧冻结列数，可为0 |
| `--freeze-through` | 可重复指定`sheet=列标题`，如`属性方案=末级类目`；冻结到指定列 |
| `--layout` | 显式样式配置，与已确认模板共用校验器；见[样式说明](excel-review-layout.md) |

默认知识只覆盖清洁纸品。其他类目不能仅换ID套用纸品资料；先准备相应`--snapshot`。他批待审、在途或失败的适用族会阻断，不能另起一套绕过。

## 真正经过的链路

1. 核对release指纹，冻结输入、范围、模型和费用配置，逐类预检字段职责、必读知识和上下文大小；缺资料、ID越界等在模型请求前报告。
2. 小卷纸族复用已审阅的七项共用选填定义和六项扩展候选，保持本批候选状态，不伪造正式发布。该合同仅用于两类普通小卷纸。
3. 配置的“大卷/中心抽大卷”“盒装/软包抽纸”先各生成一次共同方案。seed任务获得全部族成员、候选归组理由和职责，不把输出锚点类目的专有参数当成全族共性。检查通过且共同定义非空才转本批候选模板，族语义仍待人工。
4. 共同方案全部结束后一次冻结共享快照，再并发末级。准备失败只阻断该族；独立对象继续。所有叶看到相同版本的已完成基线，属性池不会随完成顺序变化。其他对象暂独立建模，可查询其他同族和池中的可复用概念。
5. 每个请求实际装入规范对应章节、后台合同、family-modeling skill及判例、字段职责、节点/祖先/相关族/属性池和适用知识。function参数/权限验证后执行本地只读工具，完整回传call_id历史；没有任意URL/文件/SQL或写入工具。
6. 最终JSON只允许去掉一个无歧义的Markdown展示外壳，不修语法或业务字段。程序独立检查结果；可将工具参数错误、范围缺失和合同错误完整反馈给模型，最多2次纠错且仍受6轮/16次工具硬上限约束，所有改动由模型重新提案并重新检查。不可用工具、未知证据、重复call_id等权限/边界错误继续硬拦。预算将尽或最后一轮用`tool_choice=none`收敛。错误原件保留但不混入可审表，模型不能批准自己的提案。所有末级成功/失败及专业疑点均进入汇总。退出码0表示执行/导出完成且无程序阻断，2表示有阻断或导出失败，1表示参数或前置错误；0仍不等于人工采用。

全范围为21叶+2次共同方案。默认`deepseek-flash`、reasoning=low，单请求240秒、最多6轮/16次模型工具调用、350000字节请求、160000字节工具结果、24000输出token。已核对2026-10-23的[官方Responses合同](https://api-docs.deepseek.com/api/create-response/)和[官方价格](https://api-docs.deepseek.com/quick_start/pricing/)。供应商别名不能固定其内部模型权重。

最多138次Responses请求。按当日Flash峰值输入$0.30/百万token、输出$1.20/百万token、输入每字节保守按1token及9元/美元折算，每请求预留1.3元，最多179.4元。默认200元是本地保守封顶配置，不是预计花费、充值指令或供应商扣款保证。实际用量与未知状态留存，账单需到供应商侧核对；资费或汇率超出假设时须显式更新价格身份。

## 结果与审阅

`batch.plan.json`给出范围、预检及上限；`batch.identity.json`冻结原快照和配置；`batch.shared-snapshot.json`记录准备后的候选族及失败族；`batch.summary.json`列全部末级状态、错误、共享费用及本次请求/缓存数。`batch.results.json`、`jobs/`、`runs/`、`requests/`保留完整候选、程序检查、工具历史、请求响应和回执。

`batch.review.json`与`review/*.xlsx`提供**属性方案、扩展候选、进度与问题**。审属性是否该设、定义、填写要求及同族差异，没有SKU试填准确率。阻断类目仍在问题表，不用“零属性”掩盖。黄色意见空白表示未审，不自动填同意。默认10pt字、22px（16.5pt）行高、全文备注；ID及配置放右侧，冻结通过参数。不同内容/样式生成不同文件名，同版文件存在就保留，避免覆盖人工意见。通用属性意见回导/正式采用未开放。

只重导或改冻结列，无模型请求：

```sh
bun src/scenarios/product_governance_v3/cli.ts batch-export \
  --out outputs/product-governance-v3/clean-paper-batch-20261023 \
  --freeze-through 属性方案=末级类目
```

导出使用Codex附带Node和`@oai/artifact-tool`，本机可直接用。其他机器缺少运行时，可设置`PGV3_NODE_PATH`、`PGV3_NODE_MODULES`指向已有Codex运行时，或先`--no-excel`。导出失败不删除成功结果，不靠重跑模型修复。

## 恢复与停止

原命令、原`--out`重跑，会逐轮重放持久响应，族版本稳定；可调并发，不可改原输入、release、模型、run-id或预算后假装原批继续。不要删请求、回执、费用账本或换目录绕过累计费用。

HTTP错误/预算不足停止派发新任务，在途任务完成并留存。超时、中断、未落盘或不完整响应保留未知回执与费用预留，不自动重发。先检查回执及供应商记录；当前没有未知请求强制重试或预算提额命令。

目录有进程锁，防止同时启动两份。强制杀进程可能留下`execution.lock`或请求锁目录；先确认旧进程结束，再人工清理相应锁，不能删回执/账本解锁。正常异常由finally释放锁。

## 宿主修复后的恢复与单类验证

2026-10-23配置说明修复更新了规范、skill和检查器，当前release不能自动把旧结果迁移为通过。用户已选择[batch-rerun全量新一轮](full-rerun-20261023.md)。下文恢复命令仅适用于业务材料/检查器均未改变的兼容宿主升级。只查看已有结果，用`batch-export --out 原纠正目录`离线生成专项复审表，无新增请求；详见[修复记录](configuration-explanations-20261023.md)。

如果只是模型返回了JSON代码块，或者旧宿主未能反馈参数错误，反复运行原`batch`命令会重放相同响应。宿主版本已更新则原批次身份检查会拦截。不要通过换目录、删缓存或清空费用台账解决。

先在项目根目录离线复核原批次。默认没有模型请求、无需密钥，不改原审阅表：

```sh
bun src/scenarios/product_governance_v3/cli.ts batch-recover \
  --out outputs/product-governance-v3/clean-paper-batch-20261023
```

复核固定原输入，核验持久请求/响应/回执和每次只读结果的hash，并要求原业务规范、skill、知识、schema、程序检查和只读工具均未变。只有明确列举的宿主/导出器代码可升级；业务材料变更须另行迁移，不能靠换release ID冒充兼容。JSON包装剥离之后仍完整运行原合同检查，R03/R07/R11等不放宽。

输出在原目录`recoveries/复核版本/`，包括`recheck.report.json`、`pending-corrections.json`、`batch.review.json`及`review/*.xlsx`。原`batch.*`、`runs/`、`requests/`、`budget.json`、人工意见均保留。默认离线复核退出码0表示复核和导出完成，是否有剩余缺口看`blocked`；它不代表21类方案都通过。

需要新模型纠正时，先选**一个失败末级**预览。例如无芯小卷纸：

```sh
bun src/scenarios/product_governance_v3/cli.ts batch-recover \
  --out outputs/product-governance-v3/clean-paper-batch-20261023 \
  --category-id 67adeef9-8c1f-47e2-ad72-462ad35a5a75 \
  --no-excel
```

`selectedPlan`给出必要同族基线及最多新增请求/费用预留。普通单类最多6请求、7.8元保守预留；需要补共同基线时两阶段最多12请求、15.6元保守预留。并非预期用量或实际账单。确认需要付费纠正时，**由用户手动在同一命令追加`--execute`**；去掉`--no-excel`则同时导出审阅表。

恢复入口暂只接受单个失败末级，不接并发或大类全量执行。共同基线失败则不请求依赖叶；已通过类直接复用。新请求继续写原`requests/`并使用同一个`budget.json`，新增候选和身份记录位于`corrections/`。同一版本的通过结果会重新校验并汇入后续审阅表。每次纠正的初始输入被固定；通过、拒绝、连接中断后原命令重跑均不静默购买另一轮，不会因其他类目后来完成而改变已启动纠正的上下文。未知请求仍保持预留，不自动重发。业务仍不合格时先研究具体问题，不靠重复执行追求通过率。

终端默认会显示`[开始]`、`[模型请求]`、`[模型响应]`或`[读取缓存]`、`[完成，待人工审阅]`。只有真实阻断走错误流；不再把全部正常日志写成红色。当前网络仍使用Bun环境代理设置，恢复不清空全局代理；该次53份记录均为HTTP200，不能把应用合同失败归因于代理。

## 验收及剩余边界

开发验收使用真实节点和登记资料装配上下文，注入构造响应验证23任务、实际工具回传、同族顺序、并发、失败、恢复、共享费用及Excel导出。真实模型请求为0，不能据此宣称DeepSeek质量或行业准确率。
