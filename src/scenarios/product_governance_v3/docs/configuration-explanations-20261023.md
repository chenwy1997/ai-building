## 实际问题与处理原则

用户的真实DeepSeek纠正响应继承7项冻结定义、6项扩展候选，但unresolved写“层数与单卷重量的精度/上限……均留null”。冻结单卷重量实际为precision=3、min=0、max=null。此前程序只检查定义/绑定、引用和继承，没有核对这段说明与当前设置。

3位精度来自既有样板代码，当前查到的专业包及规范未明确支持3位要求。保留冻结配置，不替模型补造依据，也不在末级静默改null；新增精度依据待核实项，必要时另提共享修订。

通用规则已进入规范6.5及建模/审核skill：当前配置、业务待核实问题、未来修改建议分别表述。null表示未设置，不代表专业上没有限制；false和0保持准确。规则适用于其他类目，不把“3位”或小卷纸字段做成通用标准。

## 已接通的实现

| 环节 | 实际实现与边界 |
| --- | --- |
| 统一配置投影 | `scripts/configuration-review.mjs`从同一份结构化定义/绑定生成当前事实、可读说明及精度字段依据登记缺口，供装配、检查和导出共同使用；不改业务值 |
| DeepSeek上下文 | `context.ts`装配`sharedContext.currentBaselineConfiguration`，包含冻结合同的值、程序说明及依据缺口；与skill正文和判例一起实际进入请求，参与input/release指纹 |
| R08检查 | `checks.ts`检查unresolved、属性定义/理由、绑定理由中的明确配置断言；可识别的精度/上下限、必填性、类型、公开/搜索开关与实际配置矛盾则阻断 |
| 工具与纠错循环 | 复用既有预算、只读权限及最多2次纠错；错误通过`host_contract_feedback`真正回传，模型重新提案后再检查。宿主不修业务字段，原响应继续保存 |
| 审阅材料 | 原3页保留，增加“说明核对”；属性表后置程序设置与依据缺口；进度页前置冲突摘要、后置原AI说明。当前配置和原文可对照，不把矛盾说明展示为当前事实 |
| 历史边界 | 新表标记“历史提案专项复审”。导出不重新认定整份旧合同通过，不自动复用为新付费任务；历史规范/skill/检查器漂移仍由恢复器阻断 |

断言识别是可测试的有限模式，不是完整中文语义审核。没有定位到属性的陈述保留人工核对；真实疑问、修改建议、示例及旧配置叙述不冒充当前事实。程序只提示合同未逐字段登记精度依据，不能据此证明某专业来源不存在。其他专业阈值的依据仍需人审。
