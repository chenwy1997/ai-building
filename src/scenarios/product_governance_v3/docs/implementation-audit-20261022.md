# v3规范落地审计与实施顺序

日期：2026-10-22。审计代码提交：`afc6a55f170b1b17c218511946ef3a1657e36244`。执行材料版本：`3aa75ab3a0e468a7c2d9229bd9b6449490ce398816a05d27436a0700dd2774a5`。

**结论：v3目前处于离线接线原型阶段。请求装配、四份阶段skill、九个只读工具的实际调用/回传，以及部分程序检查已落地；真实业务资料、同族基线生产与版本流转、原文到事实的准备过程、运营审核交付和后台承接尚未形成完整闭环。现阶段不具备按新规范直接跑真实批任务的条件。**

前述“已接通”准确限定为离线请求/工具/检查路径，不能扩展理解为整体规范已经实施，也不能把构造样例中的预设基线、事实和答案当成真实治理能力。

本轮只做审计、离线探针和记录。没有调用收费模型、处理真实商品批任务、修改原Excel或写入线上；运行器及业务合同未作功能修复，发布锁保持原版本。

## 1. 范围、证据和状态口径

对照[规范](governance-standard-draft.md)、[整体稿的S0—S9/R01—R26](governance-design-v1-20261022.md)、5份ADR、工具提案及接入设计；读取v3执行代码、四个skill及附件、知识包、测试和已有验收记录。

本轮重新执行45项v3测试及18项相关v2回归，**63项全部通过**，v3范围类型检查通过。另执行[20项审计探针](audit/implementation-probes-20261022.ts)，观测结果见[独立审计数据](audit/observations-20261022.json)。探针使用构造资料、模拟HTTP和禁止联网的fetch；发现的缺口没有被写成“应当保持错误行为”的通过型回归测试。

其中模拟HTTP返回一份包含九个不同工具调用的响应，九个工具均实际执行，九份结果按call_id进入下一请求，再完成最终检查。该项证明分发链路成立，不证明真实DeepSeek会正确选择工具或理解业务。

| 状态 | 本报告的含义 |
| --- | --- |
| 离线实测 | 当前执行路径被真实调用，HTTP响应由模拟器提供；能力范围限定在已测条件 |
| 部分实现 | 有对应代码，但范围不足，或审计反例已暴露漏检/误拦 |
| 文档/构造素材 | 有规则、方法说明或fixture，缺少对应业务实现、真实资料或使用闭环 |
| 有适配代码、未实测 | 例如联网Responses分支，只核对了静态接口形状，未发送真实请求 |

不统计一个“总体完成百分比”：S0资料准备和S6人工采用等业务环节缺失，不能被多个工具测试通过抵消。旧验收文件保留原证据，本报告补充其未覆盖的边界。

### 2.2 已发现的漏接与弱接

| 缺口 | 证据 | 实际影响与后续验收要求 |
| --- | --- | --- |
| **计算策略未交给模型，也没有查询入口** | [context.ts][context]输入未含derivationPolicies；[tools.ts][tools]无策略查询；P03 | 主机要求操作符、目标概念、因子顺序与策略一致，模型却不能发现允许的策略。需按目标参数预取或查询策略，验证模型可从输入自行构造合法引用；不能由mock脚本预先写好答案 |
| **必要知识目前只有构造包** | [release.ts][release]的KNOWLEDGE仅两个fixture；P05 | local快照无法使用这些包；空knowledgeIds可继续，缺口只是标记，unresolved仍可为空。需真实知识包和按类目/阶段定义的必需资料门槛；知识不足的专业项进入待研究/人工，不要求所有普通任务因缺任意资料全停 |
| **知识补查缺少发现目录** | knowledge_read只按已知ID读取；context只暴露预取命中内容 | 未命中的白名单知识没有list/search入口；类目路径关键词不是专业适用性判断。需可发现的ID、适用族、来源、状态及版本元数据，区分必需与补充 |
| **属性池前置查询容易空转** | 按完整末级名查属性name/conceptKey/definition/scope；P04：有芯小卷纸命中0，查询层数命中1 | 调用了检索不等于已参考相关定义。需按商品对象、参数概念、别名和口径组合检索，并保留拒绝复用理由；验证新族也能找到可复用定义 |
| **建模依据的引用合同不完整** | Attribute.sourceIds仅接受当前SKU的Source；P06 | 已加载知识ID反而被判“越界来源”，家族建模通常又没有单个SKU。需分开知识/专业文档引用与SKU事实引用，记录段落及适用范围 |
| **四阶段尚未形成业务数据流** | [acceptance.ts][acceptance]每阶段使用同一份预置fixture快照；P14 | 建模结果不会生成/注册下一阶段的候选基线，研究结果不形成知识版本。需接通阶段产物和依赖；同批后续请求必须引用本批实际生成的版本 |
| **部分规则章节没有进入任何阶段** | P02 | §9.2问题分级、§9.5结束条件、§11.4核验、§11.5回退、§11.6成本都未被当前规则提取覆盖。核验/回退本就属于未来执行阶段，不需要塞进所有生成请求；应为各规则登记实际执行者、阶段、程序或人工验收，已需使用的审核/结束边界不能只留在文件里 |
| **规则编号和覆盖分类过粗** | R25映射§11.1，原登记还含配置/执行保护；R02标program，humanReviewRules不含必填必要性核对 | 出现R编号不证明整条规则落实。需把结构检查、语义审核和后续执行拆成子检查；二元枚举可硬检，必填理由仍需人工 |
| **业务规范夹带旧实现状态** | 规范§8仍称具体工具未实现，末段称未建立v3入口；这些段落可能随正文进入instructions | 当前能力与旧进度说明混合。需保留业务规则、把历史状态移至明确的历史记录，运行能力用当前能力清单表达；本轮只登记，不改写已确认业务决定 |
| **共享输入前缀尚未按设计稳定** | P20；canonical按键排序，evidence/product先于sharedContext，sharedContext又包含当前类目 | instructions仍有稳定部分，但不能仅凭sharedContext名字宣称共享资料位于稳定前缀。后续在质量闭环具备后改序列化与分层，测实际前缀和缓存，不预先承诺命中率 |

### 2.3 四份skill的实际成熟度

| skill | 已有方法 | 仍缺的实施部分 |
| --- | --- | --- |
| family-modeling | 字段职责、共用定义、差异理由、单位和粒度；有芯/无芯判例 | 真实同族样板、属性池复用判定记录、新族/共享修订输出合同、定义与绑定拆分 |
| domain-research | 对象/用途/口径、专业疑点、不得伪称联网 | 真实参考材料、专业检查清单、知识发布/撤销、专家裁定入口；目前只有问题清单输出 |
| sku-filling | 证据状态、包装范围、参数级复用原则、因子引用、图片补充原则 | 原文事实提取/核实阶段、参数级外部来源准入、归属提案、图像载荷与定位、可发现的计算策略 |
| review-assistance | 接收候选程序错误、按规则提出疑点、禁止自我批准 | 对真实错误模式的覆盖、对象ID核验、人工采用与隔离记录、未参与调优的保留评估集 |

这些skill已接线，但内容仍是第一版通用方法。元数据校验和正文进入请求，不能证明足以处理五金专业参数或达到人审水平。[整体稿](governance-design-v1-20261022.md)另列的交付操作核查清单尚未建立。

### 2.4 九个工具逐一结论

| 工具 | 接线 | 业务范围限制 |
| --- | --- | --- |
| categories_search | P15实际调用/回传 | 名称/路径/别名子串；没有商品对象、用途等语义索引 |
| categories_get | P15实际调用/回传 | 读节点及祖先；没有供应链目录实例/有效属性展开适配 |
| categories_children | P15实际调用/回传 | 直接子节点/末级遍历与分页已做；只针对提供的快照 |
| find_related_categories | P15实际调用/回传 | 已登记成员＋名称二元片段相似度；不能证明自动识别同族 |
| get_family_context | P15实际调用/回传 | 区分快照中的确认/待审/在途/失败；不是实时共享注册表或任务协调 |
| search_attribute_pool | P15实际调用/回传 | 单字符串检索；定义没有完整确认/来源/适用范围索引，见P04 |
| knowledge_read | P15实际调用/回传 | 只读已登记ID；包仍为fixture，没有发现、适用性和撤销流程 |
| sources_read | P15实际调用/回传 | 只读事先准备的本SKU文本和facts；不获取后台/外部/图片资料，跨片引文有误拦 |
| calculate_value | P15实际调用/回传，仅取值阶段允许 | 冻结因子与有限算子；策略未暴露，前提冲突和因子范围仍有漏检 |

规范提到的`propose_baseline_change`没有注册、实现或调用循环；同族身份占用、发布、影响引用查询也没有对应服务。知识查证和外部补证工具不存在，不能因为skill写了查证方法就认为模型有此能力。

## 3. 新反例揭示的程序检查边界

| 探针 | 观测结果 | 判断及需要补的验收 |
| --- | --- | --- |
| P08 职责表为空，再生成品牌 | program_pass_pending_human | 确定性前置缺口。需校验职责表来源/版本/覆盖，必要字段职责缺失不能作为“不受保护” |
| P09 同一范围同时有无赠品与有赠品 | 仍算40卷并程序通过 | 真实漏检。计算前要检查所有适用前提的冲突，不能只找到一条支持性事实就放行 |
| P10 每提-10卷×每单位-4提 | 结果40并程序通过，引文与负因子均对应 | 真实漏检。计数因子本身需检查符号、整数及合理范围，不能只检结果为非负整数 |
| P11 末级必填差异提供了理由 | 仍被共同定义一致性检查一律拦截 | 合同粒度问题。requiredness、用途等类目绑定与共同定义混在Attribute中；应分别建模，明确哪些差异允许，再核实理由是否成立 |
| P12 引文跨越两个已完整读过的8000字符片段 | 被当成未读，引文对应事实也未进入任一片段 | 真实误拦。需事实字符定位/重叠读取/已读区间合并，验证跨片原文可追溯；临时再读重叠区可绕开，但默认预取未解决 |
| P13 数值精度、标题展示配置 | 作为额外字段被schema拒绝 | 表达能力未完成。原生配置虽进入提示词，生成合同却无对应字段；需定义治理合同及原生投影 |
| P16 否的引文，结构化Fact却预置true | 填true仍程序通过 | 已知语义边界，不要求字符串规则猜懂全部语义。必须补事实准备者/核实状态和人审记录，不能把facts来自JSON就当已核实 |
| P19 日期2026-02-31 | 程序通过 | 真实漏检。Date.parse可将非法日滚动到下月；需严格日历验证，并补数值范围、精度、文本及多选约束 |

还需说明：目前known值必须匹配快照中预置Fact，原文明确但没有Fact时依然被拦（P07）。这是保守检查的结果；缺的是“原文→模型提出事实/因子→程序定位及适用性核对→必要人审→固定事实版本”的实际准备流程。当前fixture已经事先给出false、3层、10卷/提、4提等结构化内容，不能据此推断模型已能从真实原文提取这些事实。

当前计算仅支持直接冻结因子的乘除和mm/cm/m、g/kg换算；没有通用公式、类别特征推导或多级派生依赖图。有限算子是明确边界，后续扩展应基于已核实业务关系；本轮没有放宽以猜测代替证据。

## 4. S0—S9完整业务链对照

| 阶段 | 当前落点 | 状态及缺口 |
| --- | --- | --- |
| S0 范围与版本 | JSON快照校验、类目索引、release指纹、manifest | 部分实现；缺真实供应链/商品只读适配、原生ID命名空间、完整字段职责及来源、批次身份和费用总账绑定 |
| S1 同族与知识 | 已登记成员/词形候选检索、知识预取、研究问题输出 | 部分实现；知识为构造，分组预置；没有完整语义判断记录、真实专业包、创建/占位/发布流程 |
| S2 共同基线与末级差异 | family-modeling按一个categoryId输出attributes，能核对已给基线 | 部分实现；缺同族共同方案产出、定义/绑定分离、原生配置、共享修改提案及下游版本流转 |
| S3 商品归属与证据 | 可读取已绑到单SKU的文本/冻结事实 | 主要为文档；无归属提案结构，Product只有单categoryId；未表示标准归属与实际挂载两条链，无外部参数准入/图像流程 |
| S4 SKU填值 | 有适用固定基线时可返回状态/类型化值及有限计算 | 部分实现；事实预先给定、若干漏检/误拦、策略不可发现；未消费本批S2输出 |
| S5 程序检查与AI辅助 | checkResult、review-assistance、程序错误随候选进入审核输入 | 部分实现；缺专业/语义能力实证、意见对象核验、严重项隔离与受影响依赖处理 |
| S6 Excel与人工评审 | 只有规则、布局试排参数和主审原则 | 文档；无v3导出器、两主视图、全文往返、结构化修订/意见回收、内容变化失效或小屏完整任务验收 |
| S7 具体变更提案 | 整体稿有数据库对象/字段承接说明 | 文档；无按对象/字段before/after、原生ID/实例、审核hash、前提/依赖/保护项的可校验提案产物 |
| S8 独立执行 | 当前没有生产写入入口 | 文档；未实现审核范围授权、服务端原子前提保护、幂等回执、逐项执行/冲突隔离；本轮也不应开启 |
| S9 回读/生效/回退 | 仅规则及接口边界记录 | 文档；无核心回读、异步搜索展示状态、部分成功核验、受保护回退方案与演练 |

当前CLI只有`offline-acceptance / plan / tree-search / freeze-release`。[整体稿](governance-design-v1-20261022.md)中的`governance run/status/resume/review-import/change-plan/apply/verify/rollback-plan`以及concurrency参数，都没有作为v3完整命令实施。

## 5. R01—R26逐条追踪

| 规则 | 实际落地 | 仍缺部分 |
| --- | --- | --- |
| R01 基础字段职责 | 接收职责表，生成/取值检查已知精确概念与名称；正文进入上下文 | 真实完整职责表、语义归属、人审及写入保护；空表P08可绕过 |
| R02 二元必填 | schema只允许required/optional | 选型必要性与理由的人审；R02不应整体标为纯program |

| R04 同族正反例 | 登记成员＋词形候选，构造跨父例 | 真实人工分组、对象/结构/用途判断、漏发现/误合并评估 |

## 6. 下一步实施顺序与完成门槛

沿用已确认的“P1契约接线→P2离线人工交付→P3代表小样→P4后台承接→P5扩量”顺序，下表将当前缺口细化。先做确定性和离线工作，真实模型小样需要另行明确范围与预算。

| 顺序 | 具体实施内容 | 交付与完成门槛 |
| --- | --- | --- |
| 1 补齐契约与上下文 | 拆分共同定义/类目绑定；补必要原生配置；分开知识引用、SKU证据及计算政策；规则登记明确程序/人工责任，清理会进入指令的过时状态 | 在不调用模型时可生成完整合法请求；模型能发现适用策略/资料；必填理由仍列入人审；不支持的后台能力明确列缺口 |
| 2 修程序漏检/误拦 | 补职责表完整性、前提冲突、输入因子范围、跨片引文、严格日期；将本次缺陷转为期望正确结果的回归 | P08/P09/P10/P12/P19等反例得到预期阻断或通过，原有保护不退化；无需付费调用 |
| 3 准备真实业务输入与专业包 | 先选有芯/无芯同族，另含包装关系及专业场景；只读导入真实类目/字段职责/商品资料，明确来源、版本和事实准备责任；建知识内容和人工代表样板/保留案例 | 每份资料与专业结论可追溯，建模依据与具体值证据分开；缺口可转研究/专家，构造包不被当真实标准；不由Codex另造一套普通属性答案 |
| 4 串起离线业务流 | 同族方案→固定同批候选版本→末级差异→SKU证据/填值→检查；实现本地提案/依赖/修订和稳定批次总账；同族并发协调在允许并发前补齐 | 用模拟模型输出从前一阶段实际产物构造下一阶段；不再从预置完整基线直接开填；变更只使相关依赖失效、同批费用不因换目录重置 |
| 5 完成人审交付闭环 | 两主视图、同族对照、全文/返回、原拟值与证据、结构化意见/修订、稳定对象＋内容版本、严重项隔离 | 无模型即可做排序/筛选/保存重开/重导出/意见回收；Mac小屏实际任务通过，Windows150%另验；未实现的专业与系统事项可见 |
| 6 受控真实DeepSeek小样 | 另行确认类别、SKU数、预算/技术尝试/业务返修上限；验收真实接口、上下文选择、工具行为和结果 | 人工按真实案例判错，报告漏检/误报、建模与值的正确性及未验范围；留出答案不进入审核器上下文；问题回流规则/知识/skill并沿依赖复查 |
| 7 后台承接与演练 | 先生成原生对象/字段before/after与已审内容hash、实例/前提/依赖/保护项；再设计受保护执行、未知回执、核心回读/异步效果和回退 | 执行前满足服务端原子保护与批准范围；演练人工并发修改、部分成功及异步失败；本轮不执行线上变更 |
| 8 再做参数化扩量 | 将已验证业务流程封装成计划/运行/状态/恢复等入口，按就绪依赖限并发；扩量与生产apply分开 | 小样及离线人审闭环过关、预算/状态/隔离可追溯后才讨论扩大范围；32是可配置示例，不是本轮动作或已证明最优值 |

第3项可与第1/2项并行准备，第5项可用构造数据先做体验；它们的业务采用依赖第4项版本与对象合同。没有必要为完成离线Excel先改线上，但S8开启前不能省略第7项。

本轮止于审计记录和实施次序，不修业务规则、不调用真实模型、不启动第6/8项任务。下一次实施优先处理第1/2项，不能用增加并发替代这些缺口。
