## 真实读取和字段职责

读取入口只允许`getProductListByStdCategoryIds`和`getProductInfo`。固定两个标准类目、首屏最多各3件、详情最多6件；无翻页、任意查询、写入动作或自动重试。已完成的采集不能被同目录新读覆盖，失败保留不含凭据的未完成回执。供应链鉴权仅由显式只读采集命令读取，通过stdin交Python标准库HTTPS，不进入命令行、回执或模型上下文；模型离线入口不读取密钥。

本轮修复了实际发现的标识错误：治理树主ID为商城类目ID，而商品列表接口需要`StdCategory.id`。首次误用商城ID得到空列表，记录保存在`roll-empty-wrong-namespace-20261022/`，不当成“无商品”结论。适配器现分别保存并校验治理/商城ID、标准类目ID、实际挂载稳定类目ID、目录实例ID、业务SKU ID和商品档案实例ID；与本地已核验树映射及原生返回的类目名称交叉核对。

样本是接口按`Product.createdAt desc`选出的最新各3件，未增加在售或本地货源过滤；实际销售状态为`FOR_SALE`。不能把它当作随机留出集、在售总体或已经确定的线上可写对象。无芯样本实际挂载于上游目录，和治理分类分开保留。

字段盘点覆盖本地源码的Product、ProductInstance、StdProduct、CategoryKeyConfig全部字段及所列商品创建/详情入口，另核对6件商品返回的74个原生属性实例。基础业务字段、技术/映射、关系、证据容器及旧参数分开处理：

- 品牌、供应商、销售单位、规格名称、交易换算、价格、条码、起订/限购、媒体、物流/售后/税务等既有职责进入实际请求中的职责表及程序排除检查，不能仅因字段当前为空而重复造属性。
- 原参数表、详情正文是证据容器。容器不作为新属性，内容中的真实物理参数可提出候选；没有沿用旧参数表为新标准。
- 商品/物流重量已有承载，不等于单卷标称质量；商品尺寸不等于纸张尺寸。按概念及对象核对，未一刀切禁止所有重量/尺寸参数。
- 本地代码版本与生产部署是否完全一致、生产CategoryKeyConfig全局自定义映射是否穷尽、职责业务语义是否被负责人确认，**仍未完成**。`complete`只表示所声明输入范围已列全，不能被解释成生产全量和业务批准。

## 人工核实与本地承接

主表前部是商品摘要、属性、候选值、引文、状态、人工结论和核实理由；ID/hash等技术列后置。只冻结短SKU定位列及表头。黄色区收集候选意见，灰色未知项不能当成可采用事实。

核实人还需确认概念、对象口径、单位及冲突已查看四项，并在SKU与问题页填写姓名/账号及UTC时间。导出脚本按稳定candidateId匹配，拒绝篡改的候选值/引文/版本、缺行/重复对象、把未知采用为事实；排序不改变意见归属。未填意见的实际交付工作簿导出0条决定，不默认为采用。

`import-fact-review`才把明确接受的初始事实变为**本地**reviewed来源，同时保存人工记录和新快照，known填写仍需引用该已核实事实。导入重做当前合同、来源、release/知识/skill版本和提取检查；资料变化、过期候选、缺少语义确认、同口径冲突同时采用均拒绝。它不进行身份认证，也不能证明署名者确实正确核实了语义。真实样板没有人工决定，本轮没有生成其已采用事实。

当前导入只处理初次空事实来源；已准备事实的修订/合并、多个SKU意见汇成一次快照及完整依赖失效尚未实现。不要将不同SKU分别导入的快照相互覆盖；后续合并应单独实现并验收。属性方案采用和线上变更也不由这个命令处理。
