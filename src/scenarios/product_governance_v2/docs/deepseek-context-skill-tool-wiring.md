## 2. 固定上下文、skill、动态资料和工具怎样配合

它们承担不同职责，不互相替代。在本项目直连API的方案中，skill是可维护的方法资料包；运行器必须读取正文和必要附件，将其编入该阶段模型实际收到的上下文。只创建SKILL.md、放进仓库或告诉模型文件名，不构成接入。

| 内容 | 采用方式 | 为什么放这里 |
| --- | --- | --- |
| 核心业务边界及当前系统能力 | 稳定instructions前缀，每阶段必带所需规则 | 二元必填、基础字段职责、SKU维度、证据状态等不能等模型想起来才检索 |
| 阶段做事方法 | 按stage读取对应skill正文、步骤和必要正反例，进入阶段指令 | 同族识别、属性建模、商品取值、审核辅助的工作方法不同 |
| 领域知识、同族基线与已有属性 | 脚本先检索，按适用族及阶段加载已固定版本的必要内容 | 专业背景要充分，也不应把全部专业资料和属性池塞给所有请求 |
| 当前类目、SKU证据、程序报错与人工反馈 | 动态任务输入，证据及意见标明是数据 | 每次任务改变；返修只带有效变更及必要依赖 |
| 按需补查 | 该阶段允许的function工具，返回带版本及定位的资料 | 解决上下文以外的疑问；不代替必需材料的预取 |
| 类型检查、计算、预算、依赖与写入限制 | 程序执行 | 这些约束不能仅靠提示模型遵守 |

**必要知识前置，补充知识可检索。** 例如建模前必须取得系统字段职责、目标类目及同族/属性池检索结果；模型可以再查某个候选的完整定义。脚本不能因模型没有主动查就省略这些前置条件。

### 一次建模请求的装配示意

以下是设计伪代码，不是已经实现的函数或可复制运行的代码：

```text
stage = family_attribute_modeling
release = 固定的规范/方法/知识/代码版本

instructions =
  核心治理边界
  + 本阶段必需规则正文
  + 本阶段skill方法正文及必要反例
  + 输出合同说明

input =
  familyContext: 已检索的同族、共同基线、适用知识、属性池命中与采用版本
  task: 当前类目、对象边界、本次范围、待解决问题及允许修改项
  evidence: 本步所需原文或可定位引用，明确已核验/未核验及适用范围

tools = 本阶段允许的真实工具定义
outputSchema = 本阶段结构化输出合同
```

同族共同资料可在多个末级请求中保持稳定前缀，当前类目和本次差异放后。全站核心规则、阶段方法、同族资料的稳定范围不同，不能全部混成一个随类目变化的“固定包”。

无缩进JSON只是序列化优化，不能代替上下文选择。稳定前缀有利于缓存复用，但命中不保证，也不证明业务质量；DeepSeek缓存基于前缀匹配且尽力提供，详见[官方缓存说明](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)。

## 3. 类目树既保留本地完整版本，也提供搜索与遍历

完整树作为本地权威快照保留；默认给模型当前节点、必要路径/候选和检索结果，而非每次要求它读整棵树再自行遍历。需要了解其他分支时通过工具补查。

以下为拟议接口，均未实现为v3工具：

| 工具 | 用途与返回约束 |
| --- | --- |
| `categories_search` | 按名称/别名/业务线索找候选，可跨分支；返回真实ID、路径、匹配说明、范围及版本 |
| `categories_get` | 按一个或一组ID取完整节点及必要边界；错误ID明确报错 |
| `categories_children` | 查直接子节点，或按明确条件返回子树末级；限定范围、分页及数量，不无限展开 |
| `find_related_categories` | 结合商品对象/结构/用途找同族候选，不只取同父节点；相似度不代替归族判断 |
| `get_family_context` | 读取成员、基线、采用范围及在途状态，区分已确认、同批待审、其他批待审和读取失败 |
| `search_attribute_pool` | 按概念、描述对象和计量口径找可复用定义；同名不自动同义 |
| `knowledge_read` / `sources_read` | 取已登记知识或证据正文及定位、版本；不能只返回标题就声称读了全文 |

搜索与列表结果至少包含treeVersion、检索范围、总数或已知覆盖情况、truncated/nextCursor以及每项定位。返回被截断时必须显式说明，不能将前几项冒称完整候选集合。遍历由程序处理循环/重复及真实父子关系，不让模型凭记忆编ID。

“拿着类目ID遍历子树”解决结构查询；“找到商品对象相同、可能跨父节点的同族”还需要业务检索和语义判断，两者不能混称已经完成同族发现。

### 以无芯小卷纸为例

1. 脚本取真实节点、路径与固定树版本，读取基础字段职责。
2. 强制检索相关类目、同族和属性池，找到有芯小卷纸等候选及已有/在途基线。
3. 核对是否同族，取得本批可用的固定共同基线和纸品知识；待审依赖仍标待审。
4. 将这些背景与建模skill一起交给DeepSeek，要求提出末级差异及理由。
5. 模型若需要确认某一重量定义，调用读取工具核对完整含义；不能因名称相近把标称重量与净重强并。
6. 程序检查结构/配置/重复及引用，人审共同定义与末级差异，结果再进入后续发布范围。

这条链才会把“同族应基本一致”变成可执行方法，而不是每个类目各带一句相同提示词。

## 4. 模型工具调用还需要真实执行循环

DeepSeek官方Responses指南支持function工具；模型提出调用后，客户端执行函数并把结果按call_id回传。当前本地provider仍按“最终JSON”处理，尚未实现这一循环。[官方Responses指南](https://api-docs.deepseek.com/zh-cn/guides/responses_api/)

拟议循环：装配必要上下文及允许工具 → 请求模型 → 校验function名称/参数/范围 → 调用真实本地工具 → 保存来源与版本 → 追加function_call及对应function_call_output → 再请求，直到得到最终结构化结果或达到本地预算/轮次上限。

Responses接口是无状态的，所需历史由客户端回传，不能依赖服务器记住本次会话或通过previous_response_id接续。[官方接口说明](https://api-docs.deepseek.com/zh-cn/api/create-response/)

轮次、单次及总结果量、并发和费用在本地运行器限制；不能只写max_tool_calls就认为生效，该参数在当前兼容表中被忽略。每阶段仅开放相应工具，普通生成阶段不开放生产写入；未知工具和越界参数不执行。[官方兼容表](https://api-docs.deepseek.com/zh-cn/guides/responses_api/)

脚本强制预取与模型补查使用同一套领域函数、版本及记录格式；不需要为两条路径复制两份语义。未接好模型循环时，可以先完成脚本预取链，但必须如实标为“预取可用、模型按需补查未实现”。

## 5. 规范成为skill之后，怎样证明它生效

建议在v3业务边界中维护建模、领域查证、SKU归属取值、审核辅助等阶段方法包；这是后续目录设计，本轮没有创建这些SKILL.md。

加载器要记录：阶段、规则ID、skill版本及正文hash、必要附件、知识/同族版本、真实请求中采用的材料和工具结果。目录或索引存在不能代替正文已读取；同一规则仍来自统一发布版本，不能在skill与prompt各手改一套。

不同阶段只加载其必需方法与材料。例如：建模重点R01—R08、R11及领域背景；填值重点R09—R16；审核辅助依据待审范围读取相应规则及错误模式。此处为分层示意，发布时须依据整体稿规则表建立完整阶段规则清单，不能用这几个范围静默遗漏其他适用规则。

| 验收层 | 能证明什么 | 尚不能证明什么 |
| --- | --- | --- |
| 读取与合同样例 | 正文确实加载，真实ID/分页/错误/来源状态可处理，前置材料缺失会阻断 | 模型已经理解专业含义 |
| 经允许的工具链小样 | 出现真实function_call，调用本地函数、回传结果并形成最终schema产物，版本/费用可追溯 | 属性及商品值已符合业务需求 |
| 人工业务样板 | 同族共同定义、基础字段排除、数量表达和证据口径等结果达到本批要求 | AI已能替代人工审核或可以全量自动上线 |
