# DeepSeek 属性建模批量运行手册

更新：2026-10-20。适用于 `cli.ts batch-*` 新入口；旧专项修订、商品试填入口仍保留。

## 已实现的顺序

1. 必填类目ID，展开指定节点下末级、去重；未知ID报错。冻结类目、标准全文、参考资料和模型配置。
2. 先产生、检查和审核公共属性“品牌”“型号/货号”，本批只做一次。各类目引用定义、分别决定必填和适用口径。其他同名字段仍允许含义不同，不强制合并。
3. 取原始ES在售商品标题、规格，逐件判断归属；只有判断符合的样本进入属性建模。可复用已有原始样本，不读取旧属性答案。
4. 从对象边界、公共识别、材料结构、用途性能、尺寸计量及包装等业务维度提出候选；记录每项用途、来源和联系。根据候选生成完整卡片及规则。
5. 程序检查类型、引用、枚举和规则；DeepSeek完整语义复核及本地震坤行参考适用性判断。只修复受影响项，最多两轮；每轮保留原响应与差异。
6. 汇总候选卡、问题和费用，进入Codex异常裁定和抽查。自动化结束不等于运营验收或线上发布。

每类完整审核一次并对修复定点重验；不是逐个属性无上下文地产生。公共定义目前在每批内部共享，尚未实现跨批次自动选用已发布公共属性库。

## 完整性与矛盾检查

新计划采用 `batch-v2-quality`，读取 `standards/10-completeness-consistency.md`。每次完整复核必须对对象边界、材质结构、计数口径、包装层级、尺寸外观、交易与SKU绑定六组给出覆盖状态、属性引用和理由。覆盖不等于每组必须新增属性；不适用要说明原因，未解决项必须留下。

程序核对六组齐全、引用存在，并提示“枚举内值被反例判枚举外”“乘法误用整除条件”“条件必填与缺项不必填混淆”“固定毫米却拒绝换算”等矛盾。提示属于复核线索，不直接替代语义判断；最多两轮局部修复后仍存在的问题进入Codex裁定。零符合样本也必须保留证据不足限制，不能自动视作验证完成。

旧 `batch-v1-layered-v2` 断点继续使用原协议与冻结上下文，不因本次更新重复付费。单元测试覆盖两个协议、恢复零重复调用及上述矛盾提示。本次只同步盒装抽纸19项裁定稿和该类5件旧样本明细，其余20类未重跑。运营验收状态仍为待审核。

## 命令

项目根目录执行。模型固定 `deepseek-flash`，`reasoning.effort=none`。并发默认32，可传1～128；实际请求数受就绪类目数量约束。

```bash
# 仅建立冻结计划，不调用模型或ES；清洁纸品二级ID展开为21个末级
bun src/scenarios/product_governance_v2/cli.ts batch-plan \
  --category-ids 8ee638a9-2cd7-4bf4-ac31-536b6a3a1f5d \
  --revision clean-paper-next --concurrency 32

# 执行上面的新计划；采集原始样本，不输入旧属性答案
bun src/scenarios/product_governance_v2/cli.ts batch-run \
  --category-ids 8ee638a9-2cd7-4bf4-ac31-536b6a3a1f5d \
  --revision clean-paper-next --concurrency 32

# 读取状态，不发起模型调用
bun src/scenarios/product_governance_v2/cli.ts batch-status \
  --revision clean-paper-next
```

以上是使用示例，未据此重跑已交付21类。省略 `--samples-from` 会通过ES采集器取样；采集器复用本版本已有取样断点。若要复用其他版本原始样本，**在创建计划和执行时均加**：

```text
--samples-from outputs/product-governance-v2/clean-paper-20261020/revisions/closure-r3
```

`--category-ids` 支持逗号分隔的多个父级或末级ID；父子重叠自动去重。`--sample-count` 默认10、范围1～50，复用样本时要求类目、数量与采样种子匹配。默认共享账本根目录为 `outputs/product-governance-v2/clean-paper-20261020`，可用 `--budget-run` 指定已有账本。

同一revision恢复时必须保留原类目ID列表、样本参数，允许调整并发。恢复读取冻结的标准和参考原文；当前文件改变不会将新标准混入旧批。新版本使用新的revision。原始样本变更会被hash检查拒绝。不要为重试随意换revision。

## 缓存与成本控制

- 标准指令固定前置；共享类目上下文、参考正文及公共定义前置；变化的任务、商品证据和问题在后。JSON无缩进、对象键稳定，保留字符串、数组顺序和业务值。
- 相同参考正文在一次请求中只出现一份，后续用来源ID引用；公共定义由程序合并，类目只输出引用和绑定。
- 两个真实未完成候选任务依次运行，再并发其余任务；不额外制造空请求预热。服务端缓存是尽力提供，统计使用实际返回的cached_tokens。
- 本地完成响应和阶段断点优先复用；未知响应保留回执，不自动重付费。已缓存的本地结果不计作服务端命中。
- 模型自身提议的伪引文、空候选占位组等可确定的格式问题由程序处理并保留审计；真实来源引用不改写。无法确定的JSON/Schema错误最多一次格式恢复，业务问题进入审核，不能无限修复。
- 预算是成本保护参数，50元不是业务成果目标。`batch-run --budget-cny 100` 可显式提高当前累计额度并记录变更，历史费用不清零。达到配置额度保留断点；不通过新账本掩盖支出。模型供应商余额另由账户决定。

公共字段虽不重复输出，完整审核仍可读取其定义。该机制减少重复，不删减必读业务规则。

## 真实验证结果

压测使用123条新增属性关系检查（含2条真实预热），不是重填历史商品。

|并发|吞吐（请求/秒）|P90|输入缓存命中|通过结构/引用检查|HTTP错误|
|---|---:|---:|---:|---:|---:|
|8|3.02|2.68秒|44.0%|15/16|0|
|16|5.30|3.09秒|94.2%|30/32|0|
|32|10.02|3.11秒|98.2%|73/73|0|

含预热的整体输入缓存命中率88.9%，估算费用0.7915元。120/123通过结构和引用检查，3条非法枚举或错误属性引用保留为异常；这些不是业务准确率。每档使用不同真实待办，缓存变化也受预热影响，不能全部归因于并发。

32是本次短任务测试范围内表现最好的档位，不是供应商上限，也不能证明完整长卡片能以同样吞吐运行。新批次按阶段记录耗时和失败，观察长输出后再调整。

另用盒装抽纸单类跑通新入口，新增14次调用、估算0.4604元，产生17项候选属性，程序检查通过，状态为待Codex裁定。原命令恢复新增调用为0。本次共估算1.2519元；费用为返回Token按账本高峰单价估算，不是供应商账单。

后续裁定：该17项候选已经Codex逐项审查，保留4项、修订12项、移出交易主数据1项，补回2项遗漏及1项共同遗漏，独立形成19项待运营审核稿。详情见该批 `codex-adjudication/盒装抽纸候选属性裁定与旧卡对比.md`。`batch-status` 同时展示历史模型流程状态和经hash核对的Codex裁定状态，不覆盖原响应。旧、新初始完整卡请求实际均为none，此比较不是思考档位A/B。

## 输出与当前边界

每批输出到 `<budget-run>/batches/<revision>/`：

- `manifest.json`：冻结标准、类目、参考和配置。
- `samples/`、`sample-hashes.json`：原始样本及一致性校验。
- `common-*.json`：公共定义、审核和确定性处理记录。
- `categories/<id>/`：候选、卡片、审核、修复、反例与来源决定。
- `candidate-cards.json`：待裁定候选集合。
- `summary.json`、`execution.json`、`运行汇总.md`：状态、异常、并发及费用。

新入口已串通属性建模到待裁定；Excel导出仍走已有报告程序，尚未集成进这一条命令。自动联网追加补证、全量商品填写、迁移和生产同步也不在该入口内。盒装抽纸本次同步记录见该批 `excel-sync/`；仅更新原交付Excel及该类当前快照，不发布到生产。
