# 属性命名与语义一致性 v1

本规范是所有类目共用的固定上下文；与属性建模、取值计量、证据和审核准则共同生效。DeepSeek依据规范提出名称、保留或修订建议，程序检查结构及引用，Codex复核异常和语义变化。不得由脚本按字数自动截短名称，也不得预置一张人工名称表让模型照抄。

## 1. 命名目标

属性名使运营、采购和商品使用者理解“这个字段描述什么”。准确、自然、可区分优先于简短；合理的现有名称保留，不为了统一外观而重写所有名称。没有硬性字数上限。

名称、定义、描述对象、字段类型、单位、计量范围、枚举、填写规则必须一致。名称不能扩大、缩小或偷换定义；“标称”“每包”“单卷”“销售总量”等有业务意义的限定词不能随意删掉。

## 2. 内容分工

- 名称写业务参数，不塞入整段取值说明、公式、枚举清单或技术ID。
- 定义解释含义和边界；单位字段承载固定单位；规则承载提取、换算、缺失、冲突处理及例子。
- 不同单位可用配套计数单位字段，但必须可从结构化定义找到与之对应的数量字段，不只靠读名称猜关系。
- 括号、斜线、“与”“或”是复核线索，不是一律禁用字符；名称长度也是提示，不是错误判据。
- 是否类型尽量使用自然的是非问句；不能仅凭名称改变类型或把未知改成否。

## 3. 一个字段的业务含义

两个概念可以同时存在、独立取不同值，且需要独立比较、筛选或计算时，应拆分。例如吸水和吸油倍率、单卷和单包的计数不能用一个裸数字混装。

组合描述有明确业务用途时可以保留为文本，例如包装规格、尺寸组合、厂商标识；要说明其结构与用途。型号与货号不是天然同义词；保留组合标识必须有明确的展示/识别用途、原文标签与冲突规则，不能假装已分清型号和货号，也不能把平台ID混入。需要分别检索两种标识时再分别建模。

数值与其计数单位、包装层级应可分别表达；销售数量单位不自动等于交易销售单位。例如“12卷/箱”中12卷的计数单位是卷，交易单位可能是箱。

## 4. 同名与同义

公共属性同一含义使用一致名称；名称相同而对象、范围或计算口径不同的，不强制合并ID。类目特性字段允许合理限定词。
跨类目不以统一名称、减少属性数或提高复用率为目标。即使两个场景下都叫“尺寸”或“适用场景”，只要描述对象、业务含义、计量范围、单位及转换、取值边界或规则不同，就分别保留类目限定的属性。只有语义及规则确实一致、有实际复用价值，并经显式确认才共享定义；类目绑定仍分别管理。非公共属性用类目ID与属性ID联合定位，名称相同或局部ID相同均不表示同一属性。

同义词可登记为历史名称或别名，不自动把近义概念等同：抽、张、片、层不能默认互换；包、提、箱不能默认互换；重量与单位面积质量不能只靠“克重”混用。

## 5. 变更分类及联动

1. 保留：当前名称自然且准确，记录理由。
2. 纯改名：业务含义、类型、单位、范围、必填条件不变，保留ID；同步名称及规则中的旧称，原始商品证据不可改写。
3. 语义澄清：保留原本意图，明确对象或范围，记录受影响规则与样本；不得借改名降低必填。
4. 结构变更：拆分、合并、改变类型或计量范围，记录旧新ID映射、条件和迁移方式；独立字段不能简单复制旧值。只有有证据支持的值才能迁移，无法区分时保留原始候选及待核原因。

新规则适用于新任务；既有运行保留原标准和模型响应。修订运行冻结新规范，记录来源卡hash、修订卡hash及采纳意见。历史来源引用中的旧名称保留，以免伪造原文。

## 6. 逐类审核清单

逐项判断名称是否清楚、是否含多余技术说明、是否丢失必要范围、是否与类型及单位一致、是否混合独立概念、是否与公共术语冲突。既要检查长名称，也要检查短名称是否过于笼统。

每项给出保留/改名/结构变更及理由。修改后检查定义、绑定、规则、公式、示例、配套单位、试填值和Excel是否一致。模型通过不等于业务验收通过；保留运营审核位置。
