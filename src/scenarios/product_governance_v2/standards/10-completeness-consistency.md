# 属性覆盖与规则一致性 v2

适用于新建批次。历史批次继续使用冻结标准，不为更新本大纲重跑已完成类目。规则不以某一旧卡为正确答案，不能只按属性数量比较质量。

## 1. 产生候选时逐维度检查

公共属性先统一定义，各类分别绑定。随后必须逐项考虑以下六组问题；不适用可省属性，但要保留简短理由。不能只给某一维度挂一个字段就视为覆盖完整。

1. `identity_boundary` 对象、用途类型、形态与相邻类边界。产品类型和使用环境分别判断；将重复身份字段转为边界检查时须保留承接项，不能静默删除。
2. `material_structure` 主体原料与结构分别考虑。纸品有层数不代表已考虑纸浆材质；配件描述其本体材质，不套用纸张属性。系列名、包装颜色不证明原料。
3. `count_scope` 独立计数口径。抽、张、片、层不默认等价；每包与销售总量区分。对有价值的独立概念作保留/不适用说明，不能用宽泛包装规格文本掩盖缺项。
4. `packaging_hierarchy` 单包、提、箱、销售组合各层级分别考虑；每提数量不能代替每箱数量。原始值、独立计算因子与最终结果分清。
5. `appearance_units` 尺寸对象、单位及外观性能。纸张尺寸不是包装尺寸；固定mm允许明确cm逐边精确换算并保留原文。压花和印花独立。
6. `sales_binding` 交易与商品属性边界、SKU/SPU及适用条件。外部标品计量单位不自动变成本类特性；包装比率不证明报价单位。型号、包装组合等会随SKU变化时不能默认SPU。

来源可用时须吸收真实差异；参考模板不是字段白名单，没写的有用属性仍可提出。模型推测枚举与实物证实的枚举分别标识，未知不塞其他。

## 2. 规则、枚举与反例同一口径

- 正式枚举已有的明确本义值不能在反例中被说成“枚举外”；如果例子是他对象、假设冲突等特殊条件，明确说明。程序只提示矛盾候选，由语义复核核定，不按字符串强行改值。
- 香型等字段优先保留原文最具体本义：原文薰衣草香就填具体值，不同时派生花香；原文仅花香才填花香。具体值不在枚举时保留真实候选；只知有香与完全未知区分。异规格组合按组件，不用多值掩盖同一单品的事实冲突。
- 条件由业务对象决定，不能由有没有资料决定。已知存在提/箱级但缺数量是missing，层级是否存在未知是applicability_unknown，明确无该层级才not_applicable。
- 数量直接值优先。计算必须同SKU同销售组合、独立直接因子、对应层级、正数；完整同质规格无赠品冲突不额外要求“无赠品”字样。包/箱不能乘提数。乘法不要求可整除；除法才检查非零除数及计数结果整数。计算与直接值不一致记冲突，不能任选。
- 完整同质多盒可判“非异质套装”，不用等“非套装”字样。组合性质不明才待确认。真实组合含其他品类不能删除组件，应另核主商品归属。
- 合成测试用“synthetic”“合成示例”“合成测试”均可，不能因缺英文单词重复修复。审核指出缺字段前要核对实际字段及当前版本，不复述已解决问题。

## 3. 样本与质量结论

已挂载不等于归属正确。matched要求正向边界证据；wrong要求明确反证；不足为uncertain。明确“塑装纸面巾”与盒装边界相反，不能当成盒装正样本。仅没写盒装时不猜软包；缺层数/抽数本身不证明错类。

没有明确正样本时，仍可出理论候选，但必须进入Codex异常裁定，不能宣称商品验证通过。定向补样与随机样本分开记录，不混算准确率。比较新旧卡先核查实际请求模型/思考参数和人工修订差异，不能把“新旧”当作思考开关实验。

## 4. 审核产物与程序职责

新批完整语义审核须返回六组coverageChecks：checkId、covered/not_applicable/unresolved、相关属性ID及理由。covered必须引用真实字段，not_applicable必须说明业务原因；未解决项进入findings。程序核对清单覆盖及ID，不把清单齐全当业务正确。

程序先生成规则矛盾线索供完整审核查看，修复后重查。程序发现的语义线索、零有效样本、清单缺项均不能因模型pass就消失，最终单列给Codex裁定。只修复问题字段和依赖，不重跑整批。旧批不增加新的付费审核阶段。

## 5. 逐概念覆盖，防止“大组通过”掩盖子项遗漏

机器清单统一定义于 `domain/quality-checks.ts::conceptChecklist`，新建与已有卡复核共用，
随标准冻结并前置到固定上下文。每个概念必须返回 `conceptChecks`：
`conceptId/status/attributeIds/reason`。状态为 `covered / not_applicable / needs_attribute`。

必须分别思考：主体原料、结构层数、计数本义、计数单位、单包数量、中间包装计算因子、
销售总量、单包容器、外层包装、压花、印花、香型。

- 这些是业务问题，**不是每个类目必须增加12个属性**。配件可以说明香型、纸浆等不适用；
  数值字段的固定单位已充分表达计数口径时，不另造单位属性。
- 纸浆原料不能由层数承接；单包容器不能代替外包装；表面纹路不能代替压花工艺。
- 抽/张/片可以是独立属性，或经适用性确认的“数量＋单位”建模；保留实际本义，不强行统一名称/ID。
- `covered` 引用实际承接ID并说明如何承接，不能仅引用公共品牌/型号。
- 缺样本、缺资料不是 `not_applicable` 的理由；业务有价值而证据不足可以先建候选并标未验证。
- `needs_attribute` 进入遗漏修复。即使总评写pass，也须进入DeepSeek定点修复；
  修复后更新概念覆盖，只重验变更及依赖。最多沿用现有两轮上限，仍未解决才交Codex，
  不增加独立的第三次全卡审核。清单完整不等于语义准确，仍保留抽检。

### 本次13条绑定的回归案例

| 类目 | 漏项 | 防漏原则 |
| --- | --- | --- |
| 抽式擦手纸 | 纸浆原料、每包张数 | 结构不代替材料；抽/张分别考虑 |
| 大卷纸、无芯小卷纸、有芯小卷纸 | 各自的纸浆原料 | 卷数、层数和净重不覆盖主体原料 |
| 软包抽纸 | 每包张数 | 已有抽数不代表考虑过按张计量的SKU |
| 湿纸巾 | 外层包装形式 | 单包容器与提/箱分层 |
| 洗脸巾 | 每提包数、提数、是否压花、香型 | 补齐计量因子；纹路不证明压花；香型独立判断 |
| 枕巾 | 单件计数单位、销售总数量 | 条/张不能混算；每包量不代替销售总量 |

这是遗漏机制的回归案例，不是以后强行复用的答案表。同名但不同场景含义的属性分别建模。

## 6. 修复不能引入新的矛盾

- “文本”“是否”不携带选项枚举；是否字段填写是/否，不偷偷改为有香/无香选项。
- 具体香型不降为有香型/花香；不增加“有香型＋百花香”这种由单值推导的重复标签。
- 完整链 `10卷/提 × 4提/箱 × 2箱 = 80卷` 可以计算，单位逐层约消；
  `12卷/箱 × 4提` 不可计算。不能机械地拒绝所有多层包装。
- `12卷/箱`只证明箱规，不自动证明销售1箱；`2装`不证明2提。
- 免打孔不证明粘贴，挂式不证明壁挂。保留缺证，不猜具体安装方式。
- 业务条件不能写成“有资料/并明示数量才必填”；有提层但缺提数仍是缺项。
- 格式、类型等确定性错误由程序拦截；语义线索交DeepSeek修复与复核，
  Codex负责剩余异常及抽查，不逐条重做普通合格卡。
