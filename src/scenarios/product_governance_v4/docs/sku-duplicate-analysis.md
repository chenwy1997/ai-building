# 商品重复候选分析

本环节在类目核查和属性规范化后执行。当前先约定输出及判定方法；不删除、合并、下架或重写商品，不阻断当前的提取、审阅和补证。

## 判断单位

- SKU 是销售规格单位；SPU 仅用于分组。同 SPU 的不同容量、包装数量、颜色不自动算重复。
- 来源记录重复、同一实物商品重复建档、同款不同供应商货源分别统计；不把多个货源当成可直接删除的业务档案。
- 标准类目相同、标题相似、图片相同只生成候选，不单独证明重复。跨类目可检索，以免错挂造成漏检。

## 候选与核对

先以可信上游平台及 SKU 标识、有效商品条码、品牌与型号等精确键找候选；无精确键时使用规范标题、类目、关键属性、规格与图片相似信息检索。条码或型号为空、占位、不可信时不作强键。

逐对核实际销售对象、容量/重量、尺寸、材质、包装层级及数量、套装包含物等。明确不同的规格必须保留差异；未知值不当相同。记录直接证据与品类推断分别参与了哪些判断。不能用重复分析中的猜测反写商品属性。

## 输出与验收

输出候选分组 ID、SKU/SPU、原类与建议类、匹配依据、关键差异、待确认事项、判定（高度疑似/待核/不同规格）、建议处理及人工意见。摘要分开报告输入 SKU、SPU、候选组、候选涉及 SKU 和已复核组；不把候选对数冒充可删除商品数。

分组不能无条件传递：A像B、B像C不证明A与C相同。组内有规格冲突时拆组或待核。后续以人工核实的同款/异款样例检查误合并和漏检，再考虑真实合并与保留策略。本轮不承诺去重准确率。
