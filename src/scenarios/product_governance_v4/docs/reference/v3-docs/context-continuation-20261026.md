# 完整上下文容量与抽纸末级续跑

## 原因与修复

来源为用户执行的`pilot-tissue-json-feedback-20261026`。4个请求产出已通过程序检查的抽纸共同基线；两个末级均在模型请求前触发`context_budget`，没有末级付费请求。真实基线上下文为200664字节，超过旧200000字节门槛664字节。预先构造的小基线未覆盖这个真实结果。

现在由同一个`stageRequest`构造器完成预检和发送：计入完整规则、skill、资料、基线、schema、工具定义、序列化转义和首轮状态。完整首请求为234956字节，在原350000字节请求上限内，剩115044字节。首请求必须至少留64000字节供后续工具/纠错消息；这只是本地容量预留，不是供应商token窗口或任意历史长度的保证。每轮仍重新检查350000字节上限，超限停止并保留结果，不裁剪正文或历史。输出token、六轮、16次工具、两次纠错、收费预留不变。

同族生成后、发出任何末级请求前，再用真实共享快照做容量预检并保存`batch.leaf-preflight.json`。真正过大时保留已完成基线；默认不自动升额度、压缩知识、另开付费轮次或重新生成基线。

`batch-continue`只接受已确认未发送请求的`context_budget`末级。先核对原始请求、响应、收据、工具读取、输出合同、程序检查和完整上下文指纹，再从原快照加已通过基线重建共享资料。任何业务材料、检查器、schema、定义或来源变化仍阻断自动复用。基线仍是原runId范围内的`candidate`，不变为正式采用。

## 本次命令

在仓库根目录执行以下命令；去掉`--execute`即为零请求预检。

```sh
bun src/scenarios/product_governance_v3/cli.ts batch-continue \
  --out outputs/product-governance-v3/clean-paper-batch-20261023 \
  --from-round pilot-tissue-json-feedback-20261026 \
  --category-ids 640b5b8b-9d6e-4784-a8e2-53c291f0b7f7,ce3a9f67-613c-4707-bf3a-95193edb8a2d \
  --reasoning-effort low \
  --concurrency 2 \
  --execute
```

只请求盒装抽纸和软包抽纸；不生成同族基线，不执行洗脸巾。输出到原批次`continuations/pilot-tissue-json-feedback-20261026/`，完成后导出两个末级的属性审阅Excel。洗脸巾仍保留在`reruns/pilot-wash-tissue-core-verified-20261026/`。这次Excel不重新合并或重评洗脸巾。

`--out`必须是原根目录，不能传源轮次子目录。模型/档位、原runId、输入、请求上限及原累计账本固定；`--reasoning-effort low`只确认原档位，不能换档。来源轮次对应一个固定续跑目录，同命令重复恢复相同请求；并发可以调整。不要新增`--round`、换目录或修改预算来处理普通失败。存在结果未知的请求时停止，不自动重发。

本次预检账本为172个历史请求、累计保守预留223.60元、有效上限280.70元，剩57.10元。两末级最多12请求，最多新增保守预留15.60元，余额足够覆盖上限。上述预留不是实际账单；运行时以原`budget.json`为准。
