## 超限根因与修复

程序限制的是初始装配上下文的 UTF-8 字节数，默认上限 **200,000 字节**。这是本地检查；这两个失败并非 API 超时或费用不足。

新共同基线生成后，末级装配加入完整定义、绑定、逐项决策、扩展候选，以及基线引用的必读资料。两个末级均达到 **202,364 字节**。预检时尚无这份新基线，所以当时通过不保证生成后仍能装入。此前离线验收覆盖了固定/较小的基线，遗漏了真实生成后体积增长这一环节。

其中阶段规则职责表已经完整放在 `instructions`，又在 `sharedContext.ruleResponsibilities` 重复放了一次，共 12,340 字节。现在只在 `instructions` 保留全文，原共享字段改为明确位置、规则 ID 清单和内容 hash 的引用；装配时必须检查完整正文确实存在。这是删除相同内容的第二份副本，不是摘要或删规则。

| 类目 | 原上下文 | 修复后上下文 | 上限 |
| --- | ---: | ---: | ---: |
| 洗脸巾 | 165,309 | 153,309 | 200,000 |
| 盒装抽纸 | 202,364 | 190,364 | 200,000 |
| 软包抽纸 | 202,364 | 190,364 | 200,000 |

每份减少 12,000 字节。阶段 skill、知识全文、同族定义与决策、引用依赖、工具声明、完整历史均保留；上下文和请求体上限、纠错上限均未提高。manifest 新增 `contextUsage`；后续超限会报告总量、上限、instructions/input 及共享组件大小，仍在请求前阻断。

这能修复本轮已复现的体积问题，不保证任何未来大小的基线都可装入。剩余容量不足时仍须显式处理任务/知识范围，不能静默截断。

CLI 汇总的 `cacheHits: 0` 统计本地完整响应复用次数，不是 provider 输入 token 缓存。共同基线首个请求未命中，随后请求大量命中；洗脸巾请求也复用了稳定前缀。本轮实际命中率支持缓存布局有效，但本次规则合同也已变化，且末级未全部完成，不能据此声称整体生成效率或质量提高。

纠错原因可复核：共同基线第一次反馈有专业状态、数量职责键、引文版本问题；第二次把 `requiredness` 放进属性定义而非绑定，违反输出 schema。洗脸巾一次反馈为数量映射使用了未登记的独立职责键 `unitMinQua`，最终改为合同中的 `unitMin`。这说明检查确实执行，也说明模型仍未一次正确遵循合同。

## 三个质量缺口的复核

| 关注点 | 本轮观察 | 尚未解决 |
| --- | --- | --- |
| 共享定义与必填冲突 | 复用 ID 的定义/配置保持一致；准入属性都是选填，必填必要性为待确认，没有旧式必填/说明冲突 | 保持原定义不等于定义适用于新类目；两个抽纸末级尚无真实结果 |
| 数量字段职责 | `facial.pack_count` 给出了计数对象、分母、计数词，以及 `salesUnit/unitMin` 同口径复用、不同包装层级独立承载的条件说明 | 未读取实际 SKU 的单位组合，条件映射尚未执行；不得声称已验证填值或张/片/抽等价 |
| 业务准入、专业定义和取值证据分开 | `admissionBasis=business_need`，SKU 值资料单列为 `unassessed`，不再以现有样本能否填写替代设立价值 | 专业适用性疑点仍可能被塞进 `unresolved`，同时标 `professionalReadiness=defined` 而进入准入属性 |

最具体的剩余问题在洗脸巾：`facial.pack_count` 沿用 `facial-tissue-package-content` 作用域，`roll.sheet_size` 来自小卷纸；模型自己写明原资料不应外推、跨族适用性需人工核实，却又标为定义就绪。共同基线也出现小卷纸资料对面巾纸的适用性待核实说明。现有程序能检查同 ID 定义一致，尚不能证明这样的跨族套用有专业依据。**本轮“程序通过”不能替代属性方案的业务采用。**

下一步优先顺序：

1. 给跨类复用补上目标类目适用性约束与回归：属性池命中仅提供候选；保持原定义与证明目标类适用是两项独立要求。对明确未核实的适用性不能仅靠改状态为 `defined` 通过，需保留为候选或提出有依据的共享定义修订；不能仅用关键词正则冒充专业判定。
2. 将数量职责键和定义/绑定字段归属的真实纠错案例加入阶段说明，帮助减少重复纠错；保留程序硬检查，不调松合同。
3. 上述离线验证后再准备同范围的新轮次；仍沿用原累计费用，保持 low 档。当前版本已变，不能直接用旧轮次名执行。现有恢复工具也不能跨上下文/业务版本自动复用旧基线、只补两类；本次未提供或执行这样的付费恢复。
