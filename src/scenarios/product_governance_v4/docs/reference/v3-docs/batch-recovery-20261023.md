## 这次补上的路径

`result-json.ts`只接受原生JSON或单个无歧义JSON代码块，不修语法、枚举、定义、配置或引文。全部原业务检查仍执行。原7个代码块案例仅洗脸巾新增通过，其余继续阻断。离线结果为3类程序通过、18类阻断，4行可审属性；程序通过仍不是业务采用。

`runner.ts`在批处理及显式单类纠正中提供最多2次模型纠错，仍受原6轮/16次工具和字节上限约束。非法JSON参数整组不执行，逐call_id返回结构化错误；null/null池范围返回真实错误。禁止工具和证据越界继续硬阻断。剩余轮数/工具额度进入实际请求，预算将尽时`tool_choice=none`。合同错误反馈给模型重新提案，不由程序替模型加display、改引用或重写冻结定义。

固定同族定义和属性池复用的区别、不可改动的类型配置、展示/搜索用途、逐字引用约束进入实际宿主协议。业务规范、skill、知识和校验器未因恢复而改版或放宽。当前仍让模型输出完整冻结定义，尚未改为“只输出继承ID与有理由差异、由合同物化”的新输出协议；真实模型纠正能否稳定对齐，须小样本验证。

`progress.ts`把正常开始、逐轮模型请求/响应、缓存和完成写stdout，真实阻断写stderr；支持human/json/quiet。不再用所有日志的红色作为失败信号。

## 原件、费用与重复执行

`batch-recover`默认离线。`batch-recovery.ts`验证原输入、持久请求/响应/回执、实际只读结果以及业务材料/schema/检查器/工具指纹。只有显式列出的宿主和导出器代码允许升级，业务合同或读取结果变化即拒绝自动复核。每个来源响应和工具历史仍可追溯。

默认输出到原目录`recoveries/`。只有指定一个原失败末级并显式`--execute`才读取模型密钥、请求纠正，必要的共同基线先行。新响应继续进入原`requests/`，使用同一个`budget.json`；原批次、原审阅意见不覆盖。

纠正记录进入`corrections/`，冻结初始输入、模型、限制、源批次、预算身份和release。已通过纠正重新检查后合并到后续审阅表；失败重跑也重放同一条纠错历史，不悄悄购买另一轮。未知响应继续保留预留和回执，不自动重发。没有重置费用、强制重发未知请求、隐式提额或全量恢复并发入口。

具体命令和退出码见[运行手册](batch-runbook.md#宿主修复后的恢复与单类验证)。
