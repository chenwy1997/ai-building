# 抽纸基线 JSON 错误定位、离线回归与补跑

## 真实原因与修复

基线第2、3、4轮原始`output_text`保存到`fixtures/pilot-core-json-failures-20261026.json`。三份逐字保留、分别核对SHA256；这里只提取最终文本，不复制请求密钥或整份运行上下文。记录是失败回归材料，不是已采用类目标准。

三个响应都在`$.decisions[3]`的`facial.contents_per_package`对象内，完成`quantity`后没有关闭外层决策对象，就开始下一个`facial.scent`对象。第2轮JSON错误位置为8261，第3、4轮为8263；第4轮加了代码围栏，原响应位置为8271。这里的偏移从0起，按UTF-16代码单元计数；行列从1起。原来解析失败只反馈“expected strict JSON or exactly one JSON code fence”，没有指出具体语法或位置，因此两次纠错重复了同一错误。

当前行为：

- `JSON.parse`仍是接收边界。它拒绝后，独立语法诊断才遍历原文，报告位置、对象路径、已解析到的objectId、最近完成的值、期待语法、实际字符和最多240字符的原文片段；不构造业务值，不补括号或改JSON。
- 裸JSON语法错误与外层围栏歧义分别报告。合法单围栏仍可去壳；不允许多块JSON或围栏外其他结构。JSON内容位置与原响应位置分别记录，覆盖中文、代理对、换行和围栏。
- 诊断进入真实`host_contract_feedback`请求，同时保存在反馈历史；最终阻断也保存诊断。模型必须自行返回完整合法对象，不能只添加围栏。片段作为待核查资料，不能改变业务规则。
- 最多两次纠错，仍在原6轮/16次工具预算内。新反馈只追加到历史尾部，完整工具配对和旧请求前缀保留。合法JSON继续经过增量装配、冻结定义、引用与业务检查。
- 深层输入和长文本只产生有界诊断；诊断不成功也不允许输入通过。相同失败轮次恢复重放持久响应，不因同一个错误静默购买新一轮。
