# 类目治理方法论 v1

2026-09-21 定稿。在真实类目（v1 13,647 节点）上实战验证，每条规则附出处案号。
配套裁决档案：`workspace/audit/review-decisions.json`。

## 0. 总原则

1. 类目树是主数据，冻结基准、稳定 ID、版本化，不每次重生成。
2. 变更以 op 为单位：rename / move / disable / add / merge / split。
3. 机器提案、机器初审、人只做价值判断，全程留痕可回放。
4. LLM 不是工作流，只是工作流里的零件；确定性规则优先，LLM 只做语义判断。

## 1. 基准与 ID 铁律

1. 原始树冻结为 v1 落库，tree_hash 防篡改，一切变更作用于版本之上。
2. ID 只在 rename / move 下存活。
3. 墓碑 ID 永不复活、永不复用；改错了向前修正（新 op 物化新版本），历史不重写。
4. apply 前整批校验，任一失败整批拒绝，不留半拉子树。

## 2. 证据三线（由便宜到贵，能便宜不贵）

1. 树内证据（零成本，确定性规则）：归一化重名、空壳中间层、杂类命名、括号变体、深度异常。工具：`audit`。
2. 商品库证据（低成本，ES）：挂载量、样本标题、跨成员标题重合度。工具：`suggest` / `tree --counts`。
3. 外部证据（中成本，联网/京东）：行业通用定义，库内证据不足时兜底。案号：接线板案。

## 3. 裁决三板斧（机器初审）

1. 看路径语境，不看名字：父级/祖先语义域不同 → 同名不同物，拒。案号：奶粉案（猫狗医疗保健 vs 母婴）。
2. 域相同，看分支冗余：同域同义才提 merge。案号：狗零食案（同在宠物生活下）。
3. 拿不准，叠商品证据：实际挂载标题是否一类东西。案号：静电消除剂案（地板除尘剂 vs 衣物喷雾，拒）。
4. 人只裁决三板斧判不了的：target 选哪边、分组维度之争、零证据拍板。

## 4. 专项规则

1. 占位名单独成类：特殊商品/其他/其它/通用/万能/各种/杂项——同名是占位语义，永不自动合并，只进 review。案号：特殊商品案。
2. 存续者看兄弟结构：不机械取路径浅/id 小者；保留分组维度一致、兄弟类目能合理存在的分支。案号：狗零食案、接线板案（target 改电气类）。
3. 类目层 ≠ 商品层：类目层的"同名不同物"常是商品错挂。类目照并，错挂商品进 Step 3 人工队列。案号：接线板案（道闸端子板错挂）。

## 5. 执行与留档

1. 流程：propose（结构校验入库）→ approve（按裁决档案）→ apply（物化新版本+墓碑+迁移地图）→ export。
2. 每个裁决带理由和证据写进 review-decisions.json：审计档案 + golden set 种子 + 下次治理的机器教材。
3. 商品机械迁移（Step 3）按墓碑地图执行，但逐商品校验标题与目标类目匹配，不匹配进人工队列。
4. 旧类目可追溯：`trace --id` 给出任意类目 id 的版本状态与完整去向链（每跳 op 类型/版本/时间），export 的迁移地图链式解析到最终存活节点（A→B→C 输出 A→C，附 hops）——商品迁移的依据。

## 6. LLM 的分工

1. 确定性规则（重名、空壳、挂载统计）：零 API，不用 LLM。
2. LLM 只干语义活：路径语境裁决（三板斧 1/2 的自动化）、空壳不同名父子判断、商品迁移校验、命名规范建议。
3. 用法：批处理、短 prompt、带证据、输出结构化 verdict（approve/reject + 置信度 + 理由）——每道题都是选择题，不是作文题。
