# 类目设计规范 v1.0

2026-09-21 定稿（待议项经 owner 裁决）。类目树设计、变更、审查的章程。机器（audit/suggest/LLM 裁决器）按本规范提案与初审，人负责修订本规范与裁决规范外情形。
案例出处：`workspace/audit/review-decisions.json`、`METHODOLOGY.md`。

## 1. 分组维度唯一性

1. 同一父级下的子类目必须按**同一维度**切分：按对象（动物/人群）、按品类（用途/形态）、按规格、按场景，四选一并保持到底，禁止混维。
2. 反面教材：「猫狗零食」按类型分（饼干奶酪/磨牙洁齿）而「狗食品/猫食品」按动物分，导致「猫狗零食 > 狗零食」成为混维异类（已并入 狗食品 > 狗零食）。
3. 维度冲突时，取"用户找货路径更直觉、兄弟类目更完整"的维度；冲突及其裁决写入决策档案。

## 2. 命名规范

1. 末级品名必须是具体商品名词（接线板、狗零食），不得使用占位名。
2. 占位名词表：其他/其它/通用/万能/各种/杂项/特殊商品/特殊用品（词表维护于 `audit.ts` GENERIC_NAME_WORDS，增补走变更记录）。
3. 括号变体（如（标准型）/（数显型））仅用于合法区分维度，同级括号维度必须统一。
4. 同级类目归一化（全半角、空白、括号、大小写）后不得重名；命名分隔符统一用「/」。

## 3. 层级与深度

1. 深度上限：一级 > 二级 > 三级 > 四级（品名），不得出现第五级。
2. 空壳中间层分两款处置（2026-09-21 修订，owner 裁决）：
   - **3.2a** 同名/名称包含的空壳（父子归一化同名，或子名仅为父名具体化）：父子合并，存续者=子。此类是历史事故无细分意图，LLM 可判批。后续类目发育需恢复层级时，add 新父级 + move 叶子挂回即可，叶子 id 与商品挂载均不受影响。
   - **3.2b** 异名独子（父子为不同概念，父是更宽分组）：不擅自合并，标「待充实观察」——父级可能是未发育的品类规划（如 粘合耗材>热熔胶棒）。一轮治理周期内用商品证据判生死：长出兄弟则保留，长不出下轮再并。
3. 同级孩子的深度应一致（不得一部分有下级、一部分直接是品名，除非该分支商品量不足以支撑细分）。

## 4. 类目唯一性与合并

1. 同一商品概念全树只保留一个末级类目；重复一律 merge，不 rename 规避。
2. 同名不同物的判定看父级语义域，不看名字（奶粉案：猫狗医疗保健 vs 母婴）。
3. 存续者优先级：分组维度一致 > 兄弟结构完整（猫零食能存在）> 挂载商品多 > 路径更规范。不机械取 id 小者。
4. merge 只作用于末级类目；被并 id 打墓碑，永不复活、永不复用，去向链可追溯（`trace`）。

## 5. 杂类（其他/通用）规范

1. 每个分支最多一个杂类节点，命名格式「其他+父级名」（如 其他电动工具）。
2. 杂类是临时收容所：每个治理周期必须拉商品证据重挂或拆分，不允许长期承载可归属明确类目的商品。
3. 杂类之间永不合并（占位语义非重复），杂类治理只走 disable/split/重挂。

## 6. 变更与迁移

1. 一切树变更走 op（rename/move/disable/add/merge/split），人审批（或 LLM 初审+人抽验），机器执行。
2. 商品迁移按墓碑地图机械执行，但逐商品校验标题与目标类目语义匹配，不匹配进人工队列（接线板案：道闸端子板不得顺进电气接线板）。
3. 每个裁决带理由与证据入档（review-decisions.json），档案是后续机器裁决的教材。
4. 零挂载末级**不主动 disable**（owner 裁决 2026-09-21）：它们是类目树的完善（预留品类位），仅当与其他类目冲突或需要合并时按需 merge/move；零挂载扫描结果只作冲突驱动处置的底账与证据。

## 7. 分组维度取向（owner 裁决，2026-09-21）

1. **食品类（主粮/湿粮/零食/奶粉/处方粮）按对象（动物）分**。理由：商品按对象设计（配方物种差异是产品事实）、用户找货对象先行、末级属性模板更干净（适用对象可固化）。执行：狗食品/猫食品各含干粮/湿粮/零食；不再设跨对象的主粮合类分支。
2. **通用品（出行/日用/玩具/清洁）按品类分**，适用对象降级为商品属性，不按对象拆假重复。
3. **「猫狗XX」合类分支统一改名「宠物XX」**（更大范围的中性描述，避免与按对象分支混淆）；细分原则：猫、狗两大主流对象可单独成支，其余对象归「其他宠物」兜底。
4. **杂类清空周期 = 每轮全量治理一次**（配合第 5 节执行）。
